# AMB-528 / AOR-010 - Surface Composition Audit

Work directly on `main`. Do not create a branch. Do not open a PR.

## Mission

Run a read-only live-source audit that maps the Red baseline screenshot failures to exact active SwiftUI files, views, strings, and structures. Do not edit UI/product source code.

```bash
rg -n "Card|HeroCard|SurfaceCard|ModuleCard|Tile|Panel|Banner|Pill|Chip|RoundedRectangle|cornerRadius|shadow|ultraThinMaterial|thinMaterial|LinearGradient|RadialGradient|background\\(|opacity\\(" Native Sources --glob "*.swift"

```

## Required Report

Create `artifacts/ambitions-ui-reconstruction/reports/AOR-010-report.md` with the required surface table, source excerpts, classifications, owner issues, and proof boundaries.

Required table columns:

```markdown
| Surface | Active root | Screenshot strings found | Root card/panel count | Local styling overrides | Banned/stale terms | Failure class | Owner issue |
```

Surfaces:

- Today -> AOR-TODAY-00
- Time -> AOR-TIME-00
- Motion -> AOR-MOTION-00
- Goals -> AOR-GOALS-00
- You -> AOR-YOU-00
- Capture -> AOR-CAPTURE-00
- Global Chrome -> AOR-CHROME-00

## Classification Values

Classify every hit as:

- active runtime
- preview-only
- debug-only
- dead/stale
- indirect/generated
- unknown

## Green Gate

- Exact files/views/line excerpts are identified for each screenshot-visible failure.
- Each failure is assigned to an owner issue.
- Preview-only, debug-only, and dead-code entries are separated from active runtime.
- No UI/product source code is edited.

## Red Gate

- Treating generated registries or old ledgers as proof.
- Assuming all Swift files are active without runtime path evidence.
- Claiming visual success or readiness from this audit.
