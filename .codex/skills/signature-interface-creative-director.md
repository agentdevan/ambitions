# Signature Interface Creative Director
<!-- markdownlint-disable MD013 -->

## Purpose

Protect Ambitions' Signature Interface from becoming generic SwiftUI cards,
dashboard panels, or decorative polish. Use this review before and after any
SI, PD, AOS24, or top-level UI batch.

## When It Applies

Use when work touches Signature Interface canon, top-level surfaces, invented
UI primitives, visual hierarchy, component naming, motion, shell, navigation,
or preview/visual QA evidence.

## Source-Truth Hierarchy

1. Current user prompt and active approval boundaries.
2. `AGENTS.md`.
3. Ambitions 3.0 source-of-truth and primitive docs.
4. PXOS surface, visual, accessibility, and Product Depth canon.
5. `docs/canon/Ambitions_Signature_Interface_System.md` when present.
6. Current SwiftUI source and tests.

## Review Inputs

- Batch prompt and dry-run selection.
- Changed files and file-size snapshot.
- Preview/screenshot evidence if UI changed.
- Component state matrix.
- Accessibility, Reduce Motion, and release-claim scans.

## Review Checklist

- Preserves `Today / Goals / Capture / Plan / You`.
- Creates or protects an Ambitions-native object, rail, lane, map, composer,
  system center, receipt, or module.
- Passes the invented-but-native rubric.
- Avoids same-size stacked cards as top-level structure.
- Has one primary visual object and clear drill-down discipline.
- Includes state, accessibility, interaction, and maintainability evidence.

## Green / Yellow / Red Criteria

- Green: average invented-but-native score is at least 4, no score below 3,
  no release/accessibility/compatibility/file-size Red, and evidence is clear.
- Yellow: minor visual or fixture gap has a named owner and does not weaken
  current or next-batch safety.
- Red: generic dashboard/card-stack drift, false implementation/release claim,
  missing UI evidence for UI work, missing component state matrix, or
  accessibility/compatibility blocker.

## Forbidden Approvals

Do not approve "make it premium", "add polish", style-only card wrappers,
fake AI glow, visual-only changes without state/accessibility proof, or
human/device/release claims without evidence.

## Required Evidence

Invented-but-native score, visual acceptance notes, preview/screenshot status,
accessibility status, file-size status, anti-generic scan, and non-claims.

## Repair Guidance

Name the missing primitive or visual object, narrow the batch, add state and
preview proof, split oversized files, or stop with Red if product identity
would be weakened.

## Claims

May claim that Signature Interface creative direction passed for the reviewed
scope. Must not claim SI implementation, human visual approval, public
accessibility proof, platform proof, or release readiness.
