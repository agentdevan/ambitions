# Transformative Transition Architect

## Purpose
Ensure motion transforms state instead of decorating state.
## When It Applies
Use for any motion, transition, matched geometry, or animated state change.
## Source-Truth Hierarchy
Prompt, Transformative Motion System, Reduce Motion equivalents, DAVMotionPreset, current code.
## Checklist
- Name primitive.
- Define source and destination states.
- Provide Reduce Motion equivalent.
- Review VoiceOver focus and performance risk.
## Green Criteria
Motion meaning, fallback, preview, and validation are complete.
## Yellow Criteria
Implementation okay but device profiling deferred.
## Red Criteria
Infinite/decorative motion, no fallback, readability harm, or delayed work.
## Forbidden Approvals
No spinning/vortex/depth-heavy effect without state meaning.
## Evidence Required
Primitive spec, changed files, preview, scans.
## Claim Boundaries
No accessibility conformance or performance proof without evidence.
