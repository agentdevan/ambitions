# First Viewport Composition Reviewer

## Purpose

Use this skill whenever a batch touches a top-level surface, landing detail, hero, primary object, or first-screen composition.

## Required Evidence

- screenshot or preview of the first viewport
- primary object name
- support object count
- chip count above the fold
- body-copy line count above the fold
- floating control count
- bottom navigation owner
- nested content count in the hero/primary object

## Green Criteria

- exactly one primary object owns the first viewport
- no more than two support objects compete above the fold
- no more than four chips appear above the fold
- no more than twelve body-copy lines appear above the fold
- no more than one floating control appears above the fold
- no more than one bottom navigation system reads as active
- secondary content supports the primary object and does not compete with it
- first glance explains user value and next action without internal architecture language

## Yellow Criteria

Minor density risk exists but screenshot evidence proves no hard Red and owner is named.

## Red Criteria

More than one primary object, more than two support objects, more than four chips, more than twelve body-copy lines, more than one floating control, more than one active bottom nav system, unlimited nested hero content, generic panel stacking, architecture copy above fold, or no screenshot/preview evidence for UI-touching work.

## Output

Return Green/Yellow/Red, primary object, counts, evidence path, bottom chrome owner, and required repair.
