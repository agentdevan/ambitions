# First Viewport Composition Reviewer

## Purpose

Use this skill whenever a batch touches a top-level surface, landing detail, hero, primary object, or first-screen composition.

## Required Evidence

- screenshot or preview of the first viewport
- primary object name
- chip count above the fold
- body-copy line count above the fold
- nested content count in the hero/primary object

## Green Criteria

- exactly one primary object owns the first viewport
- no more than four chips appear above the fold
- no more than twelve body-copy lines appear above the fold
- secondary content supports the primary object and does not compete with it
- first glance explains user value and next action without internal architecture language

## Yellow Criteria

Minor density risk exists but screenshot evidence proves no hard Red and owner is named.

## Red Criteria

More than one primary object, more than four chips, more than twelve body-copy lines, unlimited nested hero content, generic panel stacking, or no screenshot/preview evidence for UI-touching work.

## Output

Return Green/Yellow/Red, primary object, counts, evidence path, and required repair.
