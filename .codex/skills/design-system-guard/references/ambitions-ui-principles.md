# Ambitions UI Principles

## Product Feel

- Premium, calm, and consumer-focused.
- Dark-first quality bar with clean contrast, not neon noise.
- Surfaces should feel intentional and trustworthy rather than dense or corporate.

## Layout

- Favor clear hierarchy and a single dominant reading path.
- Use spacing to separate intent, not to create empty spectacle.
- Prefer a few strong grouped surfaces over many disconnected cards.

## Components

- Reuse shared primitives before inventing new component shapes.
- Keep buttons, chips, rails, and cards visually consistent with nearby Ambitions screens.
- Avoid one-off shadows, corner radii, or color accents unless a shared primitive already establishes them.

## Copy And States

- Keep copy direct, calm, and truthful.
- Empty states should explain the current product behavior without teasing unbuilt flows.
- Loading and error states should feel polished but restrained.

## Motion

- Motion should clarify state changes and preserve calm.
- Respect reduced-motion behavior already used in the repo.

## Scope Discipline

- Do not redesign unrelated screens while polishing one feature.
- If a shared primitive must change, check likely downstream surfaces first.
