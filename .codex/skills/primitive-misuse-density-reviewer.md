# Primitive Misuse Density Reviewer

## Purpose

Use this skill when a batch adds, edits, or scores a visual primitive, signature object, card, panel, list, rail, spine, field, fold, drawer, receipt, composer, or map.

## Review Checklist

- primitive has a specific Ambitions role and anatomy
- primitive usage names one density role: `flagshipPrimary`, `supportCompact`, `detailDisclosure`, `receiptDrawer`, `listRow`, or `settingsGroup`
- state matrix exists where implementation changes
- primitive does not become a generic rounded card or diagnostic panel
- density is bounded and not a dashboard pile
- repeated objects have hierarchy, not same-weight stacking
- source/trust/receipt affordances appear only where useful
- hero/primary primitives have constrained slots rather than unlimited arbitrary vertical content

## Green Criteria

Primitive identity is visible, useful, restrained, accessible, and backed by screenshot/preview evidence.

## Yellow Criteria

Existing generic debt remains but is not worsened and owner is named.

## Red Criteria

Signature object becomes a generic card, panel stack, dashboard, decorative wrapper, explanation module, chip grid, or nested panel container.

## Output

Return primitive identity verdict, density role, density risk, exact Red smell if any, and repair owner.
