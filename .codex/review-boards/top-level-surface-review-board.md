# Top-Level Surface Review Board
<!-- markdownlint-disable MD013 -->

## Purpose

Gate any work touching Today, Goals, Capture, Plan, or You top-level
composition.

## Member Roles

- Top-level surface composition reviewer.
- PXOS surface hierarchy reviewer.
- Signature Interface creative director.
- IA shell/navigation reviewer.
- Accessibility adaptive interface reviewer.
- Visual QA preview fixture reviewer.
- Release-claim safety auditor.

## Required Source Truth

Ambitions 3.0 primitive/shell docs, PXOS surface hierarchy, PXOS visual
interaction, Product Depth drill-down rules, SI canon when present, and the
selected batch prompt.

## Required Evidence Package

Surface map, one-primary-object statement, five-second glance statement,
drill-down map, VoiceOver order, preview/screenshot evidence, changed files,
file-size snapshot, and non-claims.

## Review Sequence

1. Verify no new tab or duplicate top-level destination.
2. Identify the primary visual object.
3. Verify supporting modules are subordinate.
4. Verify detail routes and drill-down ownership.
5. Check anti-card-stack and anti-dashboard rules.
6. Review accessibility order and Dynamic Type risks.
7. Review visual QA and release-claim boundaries.

## Voting And Gate Standard

Green requires all composition checks pass. Yellow may continue only when the
issue does not affect product identity, accessibility, next-batch safety, or
validation strength. Red blocks continuation.

## Invented-But-Native Rubric

Top-level surfaces must score at least 4 average and no category below 3 for
originality, native believability, usefulness, restraint, accessibility,
emotional tone, system coherence, and maintainability.

## Anti-Generic UI Review

Reject vertical stacks of unrelated generic cards, dashboards, feed-like task
lists, calendar-clone Plan, settings sprawl outside You, chat-first surfaces,
and proof/history archives as top-level screens.

## Accessibility And Adaptive Review

VoiceOver order must match visual hierarchy. Dynamic Type must retain primary
object clarity. Icons and color need text or accessibility backup.

## Preview And Visual QA Review

Top-level UI work needs preview/screenshot evidence if tooling allows. Human
visual approval and real-device proof remain unclaimed unless actually done.

## File-Size And Component Boundary Review

Surface composition must not grow existing large owner files without ME gate
approval and a documented extraction path.

## Yellow Classification Protocol

Name owner, safety rationale, revisit point, and later batch if deferred.

## Red Stop Protocol

Stop on new tab, card-stack top-level structure, generic dashboard drift,
missing primary object, missing UI proof, accessibility blocker, or unsupported
claims.

## Release-Claim Safety Review

Composition evidence is not release evidence, App Store proof, TestFlight
proof, physical-device proof, public accessibility proof, or human approval.
