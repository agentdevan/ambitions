# Release Claim Truth Protocol

Use before writing closeouts, release reports, App Store copy, demo scripts, screenshots, or readiness claims.

## Steps

1. Classify each claim as canonized, designed, implementation-scoped, implemented, previewed, tested, device-verified, or release-ready.
2. Link files/tests/previews/device proof.
3. Block claims without evidence.
4. Preserve `Candidate prepared; human approval required` unless stronger evidence exists.
5. Record remaining gates.

## Stop Conditions

Stop for human approval before TestFlight, App Store, signed release, final RC, public accessibility, or physical-device readiness claims.
