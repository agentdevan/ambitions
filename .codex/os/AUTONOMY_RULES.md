# Autonomy Rules

Ambitions autonomy is local, bounded, and repair-first.

Rules:

- Run repo doctor before and after meaningful autonomous work.
- Regenerate canon propagation outputs when canon changes.
- Refresh Codex OS context and next action whenever governance outputs change.
- Treat missing or stale generated outputs as work to repair, not noise to ignore.
- Prefer the smallest safe batch that matches current queue and proof state.
- Stop on hard Red and classify the failure rather than pushing forward blindly.
- Preserve historical records unless a truth file authorizes extraction or deletion.

Autonomy does not mean unsupervised mutation. It means the repo can explain its next safest step.
