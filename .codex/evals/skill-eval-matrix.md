# Skill Eval Matrix

| Skill | Request shape that should trigger it | Likely follow-on skill | Likely repo areas | Expected bounded step shape | Expected stop condition if blocked | Common failure pattern | Should not touch by default |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `phase-executor` | roadmap phase or risky multi-layer task needing exact repo plan | implementation skill plus `ios-qa-regression-checker` later | `docs/`, `project.yml`, `Native/Ambitions/` | plan one safe first slice before broad execution | missing seam or dependency discovered during planning | planning from generic iOS assumptions without repo inspection | unrelated UI polish files |
| `xcodegen-target-writer` | target, plist, entitlement, bundle, or scheme wiring | `ios-qa-regression-checker` | `project.yml`, plist, entitlements, target folders | target/config edits first, then regeneration notes | config can be inspected but build/signing cannot be verified here | hand-waving target config or skipping dependent files | unrelated domain logic |
| `ios-extension-builder` | widget, Live Activity, Share extension, App Intents | `xcodegen-target-writer`, then `ios-qa-regression-checker` | `project.yml`, extension targets, snapshots, routing docs | config/shared-model slice before full runtime claims | missing app-side seam or entitlements/runtime validation unavailable | writing extension code that reaches into app-only internals | unrelated feature screens |
| `capture-flow-implementer` | capture model, service, routing, inbox, source typing | `ios-qa-regression-checker` | capture domain, services, persistence, captures feature | model/service/persistence slice before UI or runtime claims | requested capture flow needs a new ingestion seam the repo lacks | collapsing captures into a generic inbox or editing only one layer | planner-only files |
| `repo-truth-enforcer` | docs truth, stale copy, removed claims | `ios-qa-regression-checker` when active shipping docs changed | `README.md`, `docs/`, previews, profile copy | one doc cluster at a time with source re-checks | repo truth still ambiguous after inspection | inventing features or leaving historical claims unlabeled | unrelated target wiring |
| `ios-qa-regression-checker` | validation or regression check ask | none | validation docs, CI workflow, changed code paths | run what is available, then report the rest explicitly | toolchain or simulator unavailable | claiming tests/builds passed without running them | unrelated product copy |
| `design-system-guard` | premium UI polish or anti-drift review | `ios-qa-regression-checker` when behavior changed materially | `Native/Ambitions/Features/`, `Sources/`, `AppUI/Sources/` | small visual cleanups on the target screen only | requested polish turns into unrelated redesign | random restyling or unrelated redesign | domain/persistence files |
| `planner-domain-safe-editor` | Today/planner/reschedule/feedback logic change | `ios-qa-regression-checker` | `Native/Ambitions/Domain/`, Today/Goals services, tests | one deterministic rule path at a time with invariant checks | broad planner rewrite or unprovable validation gap | broad rewrites with weak invariant tracking | unrelated docs cleanup |
| `release-hardening` | final preflight, merge prep, release sanity | `repo-truth-enforcer` and `ios-qa-regression-checker` | docs, plist, entitlements, project config, validation docs | docs/config/validation slices instead of a blanket readiness claim | build, signing, or manual validation cannot run here | saying the branch is ready without real checks | unrelated new feature work |
