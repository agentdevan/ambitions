## Core Rule

Every sensitive permission, picker-like private import, native-context adapter, notification grant, or user-owned sync control must have a local ledger trail that proves:

1. value was explained before any system prompt or private-data exposure,
2. the exact scope was named,
3. the user's response was recorded without raw private context,
4. denied, restricted, canceled, revoked, paused, unavailable, stale, or needs-review states degrade safely,
5. permissioned context cannot keep influencing runtime paths after revocation,
6. controls are inspectable through You / Trust & Automation / local data controls,
7. receipts explain any user-visible behavior change.

No permissioned context may silently mutate goals, Steps, schedules, learning, proof, receipts, sharing, source authority, or recovery without a ledger entry plus a local receipt/explanation.

## PermissionLedger

`PermissionLedger` is the future local-only event ledger for permission and sync-control state. It records state transitions and influence invalidation. It is not a store for raw permissioned data.

Required fields:

| Field | Requirement | Red stop |
|---|---|---|
| `ledgerEntryId` | Stable local ID generated by Ambitions. | Contains raw event title, filename, health value, location, account ID, OCR text, or private note. |
| `adapterId` | Owning native-context adapter or sync control. | Detached generic permission event with no source owner. |
| `sourceKind` | Calendar, reminders, health_fitness, location, files_photos_ocr_import, cloudkit_sync_state, notifications, focus_shortcuts, manual_life_context, or future explicit source. | Private native context is mislabeled as Source Atlas/R2/public content. |
| `permissionScope` | Exact scope, such as calendar_read, calendar_write_confirmed_block, reminders_write, selected_file_import, coarse_location_context, notification_delivery, or user_owned_sync_control. | Broad or ambiguous scope. |
| `eventType` | One of the allowed ledger events below. | Permission state inferred with no event trail. |
| `priorState` | Previous ledger state or `unknown_initial`. | Transition cannot be audited. |
| `nextState` | New ledger state. | State remains unclear after the event. |
| `valueProofId` | Stable reference to the value proof shown before prompt, or `not_needed`. | System prompt or private exposure occurs without proof reference. |
| `trigger` | User action that caused the event. | Event caused by setup wall, background scan, or hidden automation. |
| `contextSlotRefs` | Redacted IDs of ContextSlots affected by the state change. | Raw calendar/reminder/health/location/file/photo/OCR/CloudKit payload recorded. |
| `affectedInfluence` | Which path, Step, Time, schedule, trust, fallback, or receipt influence must update or invalidate. | Permissioned influence remains invisible. |
| `controlPath` | Inspectable user control path. | No way to pause, revoke, delete, reset, export, or review. |
| `receiptRef` | Local receipt/explanation ID when user-visible behavior changed. | User-visible behavior changes with no receipt. |
| `dataBoundary` | local_only, user_iCloud_state, explicit_import_local_only, user_initiated_export, or never_transmitted. | Private permissioned context can enter R2, public Source Atlas, Linear, external prompts, support, analytics, telemetry, or public share artifacts. |
| `redactionLevel` | `no_raw_private_context` by default; stricter class for sensitive sources. | Raw private material appears in ledger, logs, screenshots, Linear, or Source Atlas. |
| `freshness` | fresh, stale, unavailable, needs_review, or invalidated. | Stale permissioned state remains current. |
| `recordedAt` | Local timestamp. | No local ordering for revocation or prompt sequencing. |
| `retentionPolicy` | Retain redacted event/receipt only; delete/reset/export semantics follow local data law. | Ledger becomes undeletable hidden history or stores raw private data. |

## Ledger States

| State | Meaning | Runtime posture |
|---|---|---|
| `unknown_initial` | No prior ledger state exists. | Baseline/manual only. |
| `not_needed` | Adapter path needs no sensitive permission now. | No proof, prompt, or permissioned slot. |
| `value_proof_eligible` | User action makes proof relevant. | Show proof, no system prompt. |
| `value_proof_shown` | Proof was shown. | Prompt still blocked until user continues. |
| `system_prompt_allowed` | User continued after proof for exact scope. | Platform prompt/picker may appear. |
| `granted_limited` | User granted a bounded or selected scope. | Only scoped slots may influence. |
| `granted_read` | User granted read-only scope. | Read slots only; no writes. |
| `granted_write` | User granted write-only or confirmed write scope. | Write confirmed objects only; no broad reads. |
| `granted_read_write` | User granted read/write scope. | Read/write only within proven scope. |
| `denied` | User denied. | Baseline/manual; no nagging. |
| `restricted` | System/account/policy restricts access. | Baseline/manual or review; no hidden retries. |
| `canceled` | User canceled prompt/picker/import. | Baseline/manual; no penalty. |
| `revoked` | Prior permission/control was revoked. | Invalidate current permissioned influence and require fresh proof before re-request. |
| `paused` | User paused sync/control. | Stop current influence until resumed. |
| `unavailable` | Platform/source unavailable. | Local fallback; no account/setup pressure. |
| `needs_review` | Scope, stale state, conflict, or proof needs review. | Hold or degrade before meaningful influence. |
| `stale` | Previous permissioned slot is out of date. | Degrade to needs-review or baseline. |
| `invalidated` | Influence was cleared after denial/revocation/stale/conflict. | No current path influence. |

## Revocation Controls

Revocation means more than "permission is off." It must actively invalidate current permissioned influence.

Required revocation behavior:

| Revocation trigger | Required control behavior | Runtime fallback |
|---|---|---|
| User denies permission | Record denied, clear pending prompt path, keep Ambitions usable. | Baseline/manual context. |
| User cancels prompt/picker/import | Record canceled, do not nag, do not infer denial. | Baseline/manual context. |
| System restricts permission | Record restricted, expose review state, avoid retry loops. | Baseline/manual context or needs-review. |
| User revokes in Settings | Record revoked at next observation, invalidate ContextSlots, require fresh value proof before re-request. | Baseline/manual with receipt/explanation. |
| User pauses sync/control | Record paused, stop sync-control influence, preserve local authority. | Local-only operation. |
| Account/source unavailable | Record unavailable, avoid account pressure. | Local-only fallback. |
| Scope changes | Record scope_changed, invalidate broader influence, keep only newly allowed scope. | Exact-scope slots only. |
| Stale proof or stale context | Record stale or needs_review, hold meaningful influence. | Needs-review or baseline. |
| Delete/reset/export review | Record reviewed control action without raw payload. | Follow local data law and receipt policy. |

Revocation must not delete all historical proof by default. It must preserve redacted local receipts where retention policy allows, while removing or invalidating current permissioned influence. Raw private material must remain outside the ledger.

## Context-To-Path Influence Linkage

| Source kind | Ledger states that may influence | Allowed influence | Blocked influence |
|---|---|---|---|
| Calendar read | `granted_read`, `granted_read_write` | Busy-window/open-window summaries, Time Texture fit, Today explanation. | Raw event titles, attendees, notes, source authority, silent schedule commit. |
| Calendar write | `granted_write`, `granted_read_write` after confirmed block | Write user-confirmed Ambitions block only. | Reading availability from write-only state, hidden writes, calendar replacement claims. |
| Reminders write | `granted_write` after confirmed reminder | Write user-confirmed reminder only. | Importing Reminders as tasks or external task hierarchy. |
| Future Reminders read | Future issue only, exact scope | Narrow reminder-pressure summary. | Generic task import or shame/overdue framing. |
| Health/Fitness | Future issue only, `granted_limited` or exact proof | Coarse local energy/recovery band. | Medical/training advice, precise health values, scores, public proof. |
| Location | Future issue only, exact proof | Coarse local place/travel-friction summary. | Precise/background tracking, surveillance, home/work inference, public artifacts. |
| Files/Photos/OCR | User-selected import, `granted_limited` or explicit selection | Local Held Object/source-needed scaffold. | Background scan, raw OCR/photo/file in R2, Source Atlas, Linear, support, external prompts. |
| CloudKit sync state/control | `paused`, `unavailable`, `needs_review`, or future `healthy_after_proof` | Trust explanation, local-only fallback, conflict review posture. | Release readiness, account requirement, custom backend, private data in R2. |
| Notifications | Exact notification delivery grant | Delivery fallback and local reminder confidence. | Engagement pressure, productivity score, planning source. |
| Manual life context | User-confirmed local context | Path fit/eligibility/capacity. | Sensitive inference, protected-class targeting, public artifact. |

## Privacy Boundary

Allowed ledger material:

- stable ledger entry IDs
- adapter IDs
- source kind
- permission scope
- state/event names
- value proof IDs
- redacted trigger categories
- redacted ContextSlot IDs
- local receipt IDs
- control path IDs
- redacted fallback or invalidation reason
- local timestamps
- retention policy labels

Blocked raw material:

- raw calendar events, attendees, notes, calendar names, or locations
- reminder titles, notes, lists, or bodies
- health values, workouts, symptoms, medications, diagnoses, or training data
- precise location, home/work inference, travel trails, GPS/EXIF
- files, photos, filenames, OCR text, PDFs, private source text, URLs with private tokens
- CloudKit record payloads, account identifiers, record names, device identifiers intended for export
- local learning detail, sensitive inferred attributes, protected-class signals
- secrets, tokens, keys, diagnostics with private payloads

Forbidden destinations:

- R2 objects
- public Source Atlas packs, seeds, claims, requirements, pathing data, manifests, release receipts, or validation reports
- Linear comments containing private permissioned details
- support bundles without explicit user redaction/export action
- external prompts or hosted inference context
- analytics, telemetry, crash, or engagement payloads
- public share/progress-story artifacts
- screenshots or visual proof containing private permissioned data

## Fixture Matrix

Future implementation/validator phases must cover at least:

- value proof appears before every system permission prompt
- ledger records value proof shown before system prompt presented
- no prompt is allowed for a broader scope than the value proof
- denied Calendar read leaves Today, Time, Goals, Step, closure, and recovery usable
- Calendar write-only cannot read availability
- Calendar revoked invalidates derived busy windows and open-window candidates
- Reminders write denial keeps the Step local
- future Reminders read requires separate proof and ledger scope
- Health/Fitness denied or unavailable keeps manual energy/recovery fallback
- Health/Fitness slots contain no precise health values or medical/training advice
- Location revoked clears coarse travel/place slots and blocks precise/background assumptions
- Files/Photos/OCR canceled import creates no raw private ledger payload
- imported private material cannot enter R2, Source Atlas, Linear, support, external prompts, logs, or screenshots
- CloudKit paused or unavailable keeps local operation authoritative
- CloudKit healthy-after-proof does not claim release readiness or M23/M26 completion
- notification denied does not become engagement pressure
- stale permissioned context degrades to needs-review or baseline before influencing paths
- permission scope change invalidates broader prior influence
- delete/reset/export review records a redacted control event only
- fixture/test/generated/preview permission states are not production runtime proof

## Red Conditions

- system permission prompt appears before value proof
- permission state is inferred without local ledger trail
- denied, restricted, canceled, revoked, paused, unavailable, stale, or needs-review state breaks core Ambitions value
- revoked or stale permissioned context remains current
- permissioned context silently mutates goals, Steps, schedules, learning, proof, receipts, sharing, source authority, or recovery
- ledger stores raw private context
- private permissioned data enters R2, public Source Atlas, Linear, support, external prompts, analytics, telemetry, public share, or screenshots
- CloudKit/sync ledger claims release readiness, account requirement, M23 completion, M26 certification, or production readiness
- permission controls use shame, scores, streaks, urgency, or AI-needs-access language
