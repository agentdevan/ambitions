# Visual Object First Review Rubric

Status: Active review rubric for the five primary objects and cross-surface primitives

## Scoring

- `Green`: the object is specific, label-off recognizable, source-aware, accessible, and non-generic.
- `Yellow`: the object is directionally correct but still needs explicit boundary or linkage work.
- `Red`: the object collapses into a generic app pattern, hides source/trust, or loses the primary object.

## Review Axes

| Axis | What Good Looks Like | Common Failure |
|---|---|---|
| Reality Meridian | One dominant Today object with clear closure and receipt behavior. | Today becomes a task list. |
| Constellation Atlas | Goal threads, proof, blockers, and pivots remain relational. | Goals becomes a KPI dashboard. |
| Atmosphere Composer | Capture is input-first with route reveal and no chat persona. | Capture becomes a chatbot or inbox. |
| LifeShape Field | Time reads as capacity/pressure/protection, not a calendar clone. | Time reads as a prettier calendar. |
| User System Profile | You is a local runtime and trust control surface. | You becomes a settings page. |
| Cross-surface primitives | Trust, proof, source, receipt, and recovery stay semantically distinct. | Primitives become decorative chrome. |

## Review Questions

- Which object dominates above the fold?
- What stays visible when labels are removed?
- Which source or receipt path explains the state?
- Which recovery path is obvious without scrolling?
- Which accessibility fallback keeps meaning intact?

## Review Output

The reviewer should record:

- score
- verdict
- blocked boundary
- source-linkage gaps
- unresolved direction
- exact files that need follow-up
