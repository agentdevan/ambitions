## Install Intent

The chrome enrichment work installs a higher bar for Ambitions' app shell, persistent state, trust/proof affordances, contextual sheets, and dominant-object preservation. It is not a visual redesign request by itself. It is an authority overlay to prevent future frontend work from drifting into generic productivity chrome.

The Start Here reality-recognition refinement adds a stricter rule: Start Here is not always a recommendation surface. It is a resolver-derived aperture that recognizes the user's actual day state first. Scheduled-current work is `Active step`; user-started work is `In progress`; unscheduled local selection is `Recommended step`.

## Core Enrichment Assertions

1. Ambitions chrome is a local-first execution shell.
2. Top-level IA remains exactly `Today / Goals / Capture / Time / You`.
3. Today is the flagship chrome proof surface.
4. Reality Meridian and Start Here must stay physically and conceptually connected.
5. Local intelligence must be inspectable through receipts, source-quality lines, proof chips, and why-this drawers.
6. Primary actions must be bottom-reachable and written in Ambitions language.
7. Contextual sheets must replace disconnected generic modals for closure, recovery, reflow, conflict, and proof.
8. The app shell must preserve state continuity without becoming always-on clutter.
9. Scheduled-current work must render as `Active step`, not `Recommended step`.
10. `Recommended step` is only valid when Ambitions selects from unscheduled possible work.
11. Receipt source must match authority: scheduled-current work uses `Scheduled step`; unscheduled local selection uses `Local recommendation`.
12. `best next step`, `next best move`, `optimal move`, `Overdue`, `Failed`, and `Behind` are forbidden user-facing Start Here labels.

## Red Stop Conditions

Any implementation batch based on this install must stop red if it would:

- rename active top-level `Time` back to `Plan`
- create or promote an AI/chatbot top-level destination
- replace Reality Meridian with a generic task list
- make Start Here a generic recommendation card detached from time reality
- label scheduled-current work as `Recommended step`
- use `best next step`, `next best move`, `optimal move`, `Overdue`, `Failed`, or `Behind`
- remove local proof/receipt inspection from recommendation or adaptation flows
- silently reflow user plans without preview, receipt, or undo
- use color, motion, or glow as the only carrier of state
- claim release readiness without proof
- mutate broad unrelated source outside declared scope

## Rollback Expectations

If docs conflict with higher authority truth files, update the docs rather than weakening truth.
