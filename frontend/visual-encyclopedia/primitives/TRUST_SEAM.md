# Trust Seam

Status: Active primitive role

## Role

The trust seam is the visible handoff between state, source, proof, and user control.

## Purpose

Show the user where trust changes and how to correct it.

## Canonical Anatomy

- label
- source / proof line
- correction path
- recovery action

## Allowed Surfaces

- the five active top-level destinations
- their compatible drill-down seams
- the shared shell when trust must be visible

## Forbidden Surfaces

- ornamental separator with no state meaning
- generic card border
- hidden confidence cue

## State Variants

- fresh
- stale
- local-only
- unresolved
- recoverable

## Source / Proof / Receipt Behavior

The seam must name the source and the correction path before it implies confidence.

## Accessibility Fallback

The seam must remain understandable without color or motion.

## ADHD Safety Note

The seam should reduce uncertainty, not add another choice.

## Allowed Use

- source freshness
- correction path
- receipt confirmation
- privacy and trust disclosure

## Forbidden Use

- ornamental separator
- generic card border
- hidden confidence cue

## Visual Ingredients

- clear label
- compact disclosure
- source/proof line
- recovery action

## Misuse Examples

- decorative line with no state meaning
- hidden trust cue
- premium blur pretending to be proof

## Recipe Examples

- Today source freshness line
- You local runtime trust panel
- Goals proof trail seam

## Validator Hooks

- source behavior
- proof behavior
- recovery behavior
- accessibility fallback

## Source Linkage

The seam is source-present across the active destinations and should always point to an explicit correction path.
