## Final Intended Role
The flagship Today viewport. It presents the user’s day as one living temporal surface where the Reality Meridian is the primary object, Start Here is the current actionable recommendation, the current-time cursor is exact, and proof/recovery remain quiet but inspectable.

This recipe is the active visual lock for the North Star Today render direction. It is canon for visual intent, interaction hierarchy, ergonomics, and anti-dashboard behavior. It is not SwiftUI implementation proof, screenshot proof, release proof, or accessibility conformance proof.

## User Perception
The user should feel that Ambitions is showing one grounded day, one exact present moment, one recommended step, one reachable action, and one calm proof/recovery surface. The screen should feel alive, local, native, and emotionally safe—not like a productivity dashboard.

## Why This Surface Exists
Today needed a stronger flagship-level recipe than the older module/feed-oriented descriptions. This recipe locks the precise Today surface direction that came out of the current North Star review: a scrollable Reality Meridian with exact-time behavior, separate scheduled nodes and live current-time cursor, a one-handable Start now CTA, a sparse Start Here surface, and compact `Local · Ambitions` chrome.

## Active Top-Level IA
The bottom destination dock is exactly:

`Today / Goals / Capture / Time / You`

Rules:
- `Today` is selected on this screen.
- `Time` is the LifeShape / time-reality destination, not a generic calendar tab.
- `Capture` must not look like a chatbot.
- `Plan`, `Insights`, `Profile`, and `Habits` are not active top-level tabs.

## Flagship Viewport Contract
A valid default Today flagship viewport contains:

1. compact Today chrome
2. `Local · Ambitions` top-right trust/brand lockup
3. scrollable Reality Meridian day spine
4. exact live current-time cursor
5. scheduled step node at the step’s actual scheduled start
6. sparse Start Here content integrated into the temporal field
7. one lower-right, one-handable `Start now →` CTA
8. one small `Why this?` disclosure
9. lightweight future moments attached to the field
10. one compact receipt/recovery surface above the tab bar
11. bottom destination dock: `Today / Goals / Capture / Time / You`

Do not show every possible Today system fully expanded in the default viewport.

## Temporal Model
The Reality Meridian must distinguish **scheduled anchors** from **the live present**.

### Scheduled Step Node
The scheduled step node marks where the active or recommended step belongs on the day spine. If a step started at `10 AM`, the `10 AM` node remains visible as the scheduled anchor even after time has moved forward.

### Live Current-Time Cursor
The current-time cursor marks where the user is now. It is exact, not approximate. If the current time is `12:15 PM`, the glow sits at the precise `12:15 PM` position on the rail, with the label `12:15 PM` aligned on the left.

### Required Example
If the Start Here step is scheduled at `10 AM` and the actual current time is `12:15 PM`:

- keep a clear scheduled step node at `10 AM`
- place the live glow/cursor at `12:15 PM`
- show `12:15 PM` as the exact left-side label
- keep the active Start Here content visible on the right
- do not merge the scheduled node and live cursor into one glow

The live glow should feel like a soft temporal cursor: radiant, native, calm, and premium. It must not read as an alarm, warning, gamified energy meter, or sci-fi effect.

## Scroll Behavior
The Reality Meridian is a scrollable vertical day spine. A visible screen is only one viewport state, never the complete day.

Rules:
- imply continuation above and below the viewport
- support scrolling through additional tasks, commitments, protected blocks, recovery moments, and open loops
- preserve exact time placement while scrolling
- allow tapping moments/nodes for lightweight detail
- keep the current-time cursor grounded in the visible time scale when present
- avoid making the rail feel like a finite static task list

## Compact Top Chrome
Top chrome is compact, safe-area-aware, and subordinate to the day surface.

Required visible chrome:
- `Today`
- date/context, for example `Thu, May 14 · Morning`
- right-side local-first lockup: `Local · Ambitions`

Preferred `Local · Ambitions` treatment:
- small green local/privacy indicator bead
- text `Local · Ambitions`
- aligned with the top-right chrome/status area
- quiet native status treatment, not a marketing logo

Forbidden chrome treatments:
- large standalone Ambitions wordmark in empty space
- marketing banner
- thick header
- top-level chatbot button
- standalone `On-device` wording as the primary brand/status lockup

## Start Here Surface
Start Here emerges from the Reality Meridian field. It is not a rectangular dashboard card, AI suggestion box, or top hero tile.

Default visible content is sparse:
- `Start here`
- step title, for example `Draft the interview story`
- metadata, for example `35 min · Work context`
- reason, for example `This open block fits with buffer.`
- quiet proof line, for example `42m open · 7m buffer · Local`

Default Start Here must not expose all reasoning, all receipts, all tags, all chips, all pressure metadata, or all action alternatives at once.

## Primary CTA
Primary CTA:

`Start now →`

Ergonomic rule:
- one-handable
- on the right half of the interface
- at or below the screen’s vertical center
- lower-middle / right thumb-reach zone
- visually strongest actionable object
- clean, floating, native pill button

Forbidden CTA treatments:
- top-left primary CTA
- CTA high inside a top hero card
- equal-weight action button row at rest
- hard elbow line, wire, circuit trace, or diagram connector from the rail to the button
- hidden or secondary-looking primary action

The active node may influence Start Here through proximity, soft glow, radial field, or spatial alignment. Use light and hierarchy instead of explicit wiring.

## Secondary Action
Default secondary action:

`Why this?`

Rules:
- one small secondary affordance near the CTA
- opens inspectable recommendation/source explanation
- never competes with `Start now →`
- do not show `Adjust plan` as an equal-weight default button in the flagship viewport

## Day Flow
Visible future moments are field-attached and lightweight, not boxed task rows.

Example visible moments:
- `2:00` / `Support queue`
- `6:10` / `Utilities checklist`
- `9:25` / `Wind down`

Rules:
- use exact times when shown
- keep metadata minimal
- avoid colored evidence pills on every item
- avoid row-heavy list styling
- avoid generic task-list or calendar-grid feel
- preserve temporal spacing and scanability

## Receipt / Recovery Surface
A compact proof/recovery surface may sit above the bottom tab bar.

Canonical example:

`Still counts. Yesterday’s step was moved.`
`Receipt saved · 8:42`

Rules:
- compact
- calm
- glassy / graphite-integrated
- emotionally safe
- object-attached to Today/Reality Meridian
- not an error state
- not an overdue warning
- not four closure chips by default
- not an expanded receipt drawer by default

## Visual Style
The surface should feel:
- premium
- native iPhone-first
- living
- local-first
- inspectable
- warm dark graphite
- calm and spacious
- one-handable
- recovery-aware

Use:
- warm dark graphite, soft black, deep charcoal
- faint blue-black depth
- restrained gold/amber highlights
- soft temporal glow
- subtle celestial orientation only where it supports relationship/field meaning
- SF Pro-like native typography
- native safe areas and Dynamic Island spacing
- graphite/glass material restraint

Avoid:
- dense dashboard layout
- card-stack default
- productivity template visuals
- generic task rows
- colorful dashboard widgets
- neon cyberpunk
- sci-fi overstatement
- motivational filler
- web app chrome
- hamburger menu
- chatbot UI

## Label and Copy Rules
Use:
- `Start here`
- `Start now →`
- `Why this?`
- `Local · Ambitions`
- `Still counts.`
- `Receipt saved`
- `Recommended step` only where an explicit supporting label is needed

Avoid:
- `Your best next move`
- `Recommended next step`
- `Begin Focus`
- `Start Focus`
- `Plan` as a top-level destination
- AI confidence/model jargon
- shame, streak, score, or failure language

## Accessibility Intent
The surface must preserve meaning without depending on color, glow, motion, or small type.

VoiceOver order:
1. Today
2. date/context
3. `Local · Ambitions`
4. Reality Meridian
5. live current-time cursor and exact time
6. scheduled Start Here node
7. Start Here step title
8. fit/proof line
9. primary action `Start now`
10. `Why this?`
11. upcoming moments
12. receipt/recovery surface
13. tab bar

Dynamic Type:
- preserve the Reality Meridian, exact current time, Start Here title, proof line, CTA, and recovery surface first
- collapse secondary decorative atmosphere before collapsing meaning
- allow future moments to reduce to time/title pairs

Reduce Motion:
- replace cursor motion with static exact-time label, static node, and before/after summary
- no meaning may depend only on animation, parallax, or glow

Reduce Transparency:
- graphite opaque surfaces preserve hierarchy when blur/glass is disabled

Increase Contrast / Differentiate Without Color:
- current cursor, scheduled node, CTA, proof, and receipt state require labels, position, and shape in addition to color

ADHD density law:
- one dominant temporal object
- one recommended step
- one primary action
- one quiet proof/recovery surface
- no competing CTA cluster at rest

## Native iPhone Believability Requirements
The Today flagship surface must feel like a shipping native iPhone app:
- respects Dynamic Island and safe areas
- uses native-scale typography and touch targets
- keeps the primary CTA in a real thumb zone
- uses bottom destination dock conventions
- avoids custom novelty chrome that fights iOS
- avoids web/dashboard layout density
- keeps text crisp and sparse

## Anti-Generic Acceptance Gate
Fail this surface if any of the following are true:
- Reality Meridian can be replaced by a generic task list without losing meaning
- Start Here reads as a card in a dashboard stack
- `Start now →` is above center or left-weighted
- scheduled node and live current-time cursor are collapsed into one ambiguous marker
- `Local · Ambitions` is missing from top chrome
- proof/recovery is absent or over-expanded
- the viewport shows too many equally weighted modules
- the screen reads as calendar clone, chatbot, or productivity dashboard

## Supersession Notes
This recipe supersedes any active Today visual direction that defaults to:
- dense module feeds
- top hero card with many chips
- Now / Next / Later boxed task rows as the dominant structure
- four closure chips visible by default
- full receipt drawer visible by default
- standalone `On-device` chrome without Ambitions branding
- large floating Ambitions logo/wordmark
- primary CTA placed high or left

Older recipe files may remain as supporting object-level detail, but this recipe owns the flagship Today viewport composition and hierarchy.
