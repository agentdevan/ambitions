# UI Studio Operating System

Status: Active frontend control-plane guide
Authority: subordinate to `docs/truth/*` and `frontend/visual-encyclopedia/FRONTEND_AUTHORITY_INDEX.md`

This document installs the Ambitions UI Studio operating system for future flagship UI work. It is a control-plane artifact, not product proof.

## Purpose

UI Studio exists to keep Codex behaving like a disciplined native iPhone frontend team instead of a generic UI generator.

The operating system must:

- preserve the active top-level IA: `Today / Goals / Capture / Time / You`
- treat `Plan` as compatibility-only unless current truth explicitly widens it
- keep one primary object per root surface
- prefer surface topology, state coverage, proof, and truth over decorative styling
- make preview and screenshot work stateful, not aspirational
- do not use dashboard, task-list, chatbot, or calendar-clone defaults

## Installed Canon

The flagship object canon is:

- Today = Reality Meridian + Start Here
- Goals = Constellation Atlas
- Capture = Atmosphere Composer
- Time = LifeShape Field
- You = User System Profile + Trust & Continuity

The UI Studio stack must keep those objects visible in the prompt family, the review board, and the screen-state matrix.

## Operating Loop

1. Read the active truth files first.
2. Read the frontend authority index and the relevant surface recipe.
3. Pick the surface state coverage from `trace/UI_STUDIO_SCREEN_STATE_MATRIX.md`.
4. Generate a bounded implementation prompt with the runner metadata header.
5. Keep source scope narrow and explicit.
6. Require proof artifacts for changed screens.
7. Run drift, binding, proof, accessibility, and anti-generic checks before any closeout claim.

## Quality Bar

UI Studio work must satisfy all of the following:

- native iPhone believability
- calm shell with rich panels
- inspectable intelligence without model jargon
- no shame language, fake urgency, or generic productivity framing
- accessible hierarchy, Dynamic Type resilience, VoiceOver order, and reduced-motion alternatives
- visible gesture alternatives for important actions
- no color-only state meaning
- no duplicate token systems or parallel canon paths

## Hard Stops

Do not use UI Studio to:

- reintroduce `Plan` as top-level IA
- do not build generic dashboard or task-list surfaces
- claim screenshot, accessibility, performance, or release proof from docs alone
- widen a bounded surface brief into a full redesign
- create a second frontend authority root
