## Outcome

For one stable adopted destination, the user receives a source-grounded,
generatively composed Goal Path Proposal with ordered stages, dependencies,
alternatives, authority boundaries, optional preparation, current conditions,
unknowns and a versioned change explanation. It remains a private draft until
the existing Goal Path owner revalidates and the user confirms exact adoption.

## In scope

- Exact Goal/destination/public-release input and private starting-context
  snapshot.
- Deterministic Route Evidence Graph and semantic classification.
- Registered structured generative composition from closed aliases only.
- Complete typed node/edge/authority/source/current/unknown/provenance model.
- Progressive stage/node/source inspection and editable user-controlled work.
- Multiple materially different route handoff to existing comparison owner.
- Versioned regeneration deltas preserving accepted/completed progress.
- Deterministic/manual fallback, sparse/source-needed states, deletion,
  accessibility and evaluation.

## Out of scope

- Destination choice/change, Goal creation, route winner selection, canonical
  Path activation/replacement, Step/Proof creation, schedule placement/reflow,
  multi-Goal simulation or external action.
- Invented requirements/equivalencies/current opportunities, personal
  eligibility/readiness/success prediction or universal route score.
- Hidden auto-regeneration, hosted private search, arbitrary browsing or model
  access to canonical command clients.

## Requirements

### REQ-001 — Stable intent gates generation
Input binds exact Goal/outcome/destination/route revisions; an outcome change
returns to destination adoption and never silently replans another goal.

### REQ-002 — Evidence graph is the factual ceiling
All public route identities, requirements, alternatives, relationships and
current claims enter through admitted exact claims/use profiles. Private facts
are separately typed. The model cannot introduce source-owned facts.

### REQ-003 — Route semantics are explicit
Nodes/edges distinguish authority requirement, preparation, optional support,
official alternative, decision, selection, authority outcome, post-selection,
review, conditional opportunity, Proof expectation, recovery and closure, plus
requires/one-of/all-of/support/after/conditional/not-before/review semantics.

### REQ-004 — Personal state is never inferred satisfied
Capability, Proof, education, experience, resource, location, health and other
facts are confirmed/unknown/not-included/conflicting/corrected. Similarity or
absence cannot mean met, unmet, equivalent, eligible or disqualified.

### REQ-005 — Composition uses the private runtime
A registered task receives closed aliases/minimal context through read-only
tools and returns an untrusted structured graph. Deterministic validation owns
admissibility; no model/provider/source direct path exists.

### REQ-006 — Every source-owned element is inspectable
Show authority, claim, purpose, region/program, version/effective context,
retrieval/freshness, conflict and limit. Generated generic work is clearly
unsourced and cannot retain a source badge after editing.

### REQ-007 — Structure is complete and bounded
A proposal provides start/current position, ordered stages, dependencies,
alternatives, requirements, resources, constraints, assumptions, unknowns,
risks, Proof expectations, decision/review points, closure and next clarification.
Depth/size budgets yield progressive detail or smaller truthful output.

### REQ-008 — Conditional/current states remain honest
Closed/unknown opportunities remain conditional. Expired/conflicting current
claims invalidate only dependents and cannot erase the durable route.

### REQ-009 — Users can revise the proposal without falsifying sources
Users can split/combine/rename/reorder/omit/restore generated user work, correct
private facts/assumptions, inspect sources, reject/defer/regenerate or build
manually. Editing source meaning removes attribution and triggers revalidation.

### REQ-010 — Material alternatives go to comparison
If candidates differ materially in authority route, prerequisites, resources,
time envelope, reversibility or risk, the generator must not choose a winner;
it hands immutable candidates to the comparison owner.

### REQ-011 — Adoption is downstream and explicit
One reviewed proposal creates a revision-bound activation input only. Goal Path
owner revalidates sources/private facts/dependencies and previews exact Path/
Step/Proof scope; scheduling remains separate.

### REQ-012 — Regeneration produces an inspectable delta
New proposals classify retained/moved/conditional/added/unsupported nodes and
why. Completion and accepted history are preserved; model changes alone cannot
rewrite canonical state.

### REQ-013 — Failures preserve deterministic/manual value
Sparse/invalid/stale sources, unavailable model, invalid graph, cancellation or
changed inputs return sourced envelope/generic/manual/v1 composer as applicable,
without canonical mutation or fabricated authority.

### REQ-014 — Lifecycle is revision-safe and deletable
Drafts bind all dependencies; stale async results discard. Save/migrate/replay/
archive/delete/purge are idempotent and crash recoverable; deletion cannot remove
accepted canonical/history/source owners or resurrect removed drafts.

### REQ-015 — Privacy and security remain local-first
No private Goal/path/capability/Proof/resource/constraint content enters public
requests, telemetry or unauthorized hosted modes. Injection, cycles, graph bombs,
unsafe markup/links and tool escalation fail closed.

### REQ-016 — Evaluation is route/task/version bound
Measure graph/source validity, semantic accuracy, unknown preservation,
granularity, alternatives, capability continuity, delta stability, privacy,
bias/dignity, correction, accessibility, performance and user usefulness.

### REQ-017 — Route meaning is fully accessible
Ordered list views communicate all graph semantics without a diagram; controls,
sources, branches, deltas and states support assistive technologies and do not
frame long routes or unknowns as personal failure.

## Acceptance criteria

- AC-001: changed Goal outcome blocks and routes to destination adoption.
- AC-002: invented IDs/requirements/relationships/current facts fail validation.
- AC-003: every node/edge semantic distinction survives round-trip/rendering.
- AC-004: absent/similar Capability or Proof never becomes gate satisfaction.
- AC-005: only registered private-runtime task executes; no command path exists.
- AC-006: every source badge opens exact evidence; edited facts lose attribution.
- AC-007: graph completeness/budget tests yield valid progressive/fewer output.
- AC-008: closed/expired current claim affects only conditional dependents.
- AC-009: every edit/correction/reject/manual action is non-mutating and replayable.
- AC-010: material alternatives cannot be silently ranked/adopted.
- AC-011: activation input causes no mutation until owner confirmation.
- AC-012: delta fixtures preserve completion and explain every change.
- AC-013: each source/model/security failure retains truthful fallback.
- AC-014: race/fault/migration/purge proves stale discard/deletion terminality.
- AC-015: private canaries and injection/graph attacks fail every boundary.
- AC-016: hard-gate evaluation passes per route/task/model/source slice.
- AC-017: assistive/device/direct-user proof covers overview through delta.
