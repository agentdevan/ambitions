## Migration Matrix

The current ledger names every SwiftData persisted record and the portable snapshot schema. AFRI-009 adds `StorageSchemaVersionLedger.seededHistoricalV0`, a deterministic historical ledger fixture that downgrades each SwiftData record version while keeping the current ledger schema format.

The migration matrix is generated by `StorageMigrationPlanScaffold().plan(from: .seededHistoricalV0, to: .current)`:

- every SwiftData record becomes a `version_change` entry;
- every mutation entry requires storage invariant check, pre-migration backup, staged dry run, restore rollback plan, user review, and release-claim block gates;
- execution remains disabled by default.

## Recovery Boundary

`StorageMigrationRecoveryCoordinator` creates an inspectable `StorageRecoveryAssessment` and `StorageRecoveryReceipt` before migration or recovery action. The receipt includes SourceRecord, Receipt, and ReplayTrace IDs and routes inspection through You / What Ambitions knows.

Corrupt-store signals open `corruption_review_required` mode. Destructive reset remains disabled by default and requires explicit user action after backup/export review.
