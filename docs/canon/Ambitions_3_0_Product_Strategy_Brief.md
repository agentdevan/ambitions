## Purpose

This brief defines what Ambitions 3.0 must prove as a product rebuild.

Ambitions 3.0 is not a visual refresh. It is the rebuild of Ambitions into a premium iPhone-native life execution system.

---

## Product Thesis

Ambitions helps raw intent become placed structure, placed structure become believable plans, believable plans become one clear step, real life become closure, and progress become proof.

```text
Capture → Place → Plan → Do Today → Close / Recover → Save Proof
```

---

## What Ambitions Is

Ambitions is a premium iPhone-native life execution system for:

- ambitions
- goals
- steps
- planning
- capture
- recovery
- proof
- receipts
- trust
- self-direction

---

## What Ambitions Is Not

Ambitions is not:

- a task manager
- a calendar clone
- an AI scheduler
- a focus timer
- a habit tracker
- a project-management board
- a productivity score app
- a streak app
- a chatbot
- a notes app
- a generic planner

---

## Unique Product Insight

Most productivity apps assume the user needs more tasks, schedules, reminders, or automation.

Ambitions assumes the user needs:

1. one believable next step
2. a safe place to put raw intent
3. a plan that respects real life
4. recovery when reality changes
5. proof that progress still counted
6. trust over what the system changed or learned

---

## Target User

Ambitions is for people whose lives are too complex for a checklist but too personal for project-management software.

Primary user traits:

- ambitious but overloaded
- long-term goals feel important but hard to execute
- needs help turning thoughts into structure
- wants planning without shame
- may struggle with executive function, time blindness, or follow-through
- values privacy and control
- wants a beautiful app that feels serious, not cute

---

## Primary Jobs To Be Done

1. When something important is in my head, I want to place it safely so I can trust I will not lose it.
2. When I open the app today, I want to know where to start without re-planning my life.
3. When my plan breaks, I want to recover without feeling like I failed.
4. When I make progress differently than planned, I want it to still count.
5. When Ambitions recommends something, I want to understand why and be able to change it.
6. When my goals are long-term, I want to see the path, proof, risks, and next visible step.
7. When life gets crowded, I want to know what can realistically hold.

---

## Product Pillars

### 1. Start Here

Ambitions should make the next believable step obvious.

### 2. Place Everything

Every meaningful input gets a destination, safe temporary state, or correction route.

### 3. Plan Reality

Plan is a full Life Planning Suite, not a calendar clone.

### 4. Close The Loop

Reality gets resolved through closure, not shame.

### 5. Save Proof

Progress becomes evidence the user can trust.

### 6. User Control

Automation, memory, recommendations, and plan changes remain visible, explainable, and correctable.

---

## 3.0 Success Criteria

Ambitions 3.0 succeeds when a user can complete this loop:

```text
Open Ambitions
Capture something meaningful
Place it
See how it fits a goal or plan
Open Today
Start one recommended step
Close what happened
Save proof
See what changed
Correct anything wrong
```

## Internal Product Metrics

These are internal metrics only. They must not become user-facing scores.

- first useful object completion
- capture-to-place completion
- placement correction rate
- recommended step start rate
- step detail open rate
- step session completion or closure rate
- Still Counts usage
- closure completion rate
- proof saved rate
- receipt peek open rate
- plan reflow approval rate
- memory correction rate
- low-energy/recovery mode usage
- no-schedule setup completion

---

## Release Thesis

The first mature Ambitions 3.0 release should not prove every invention.

It should prove:

1. Capture is safe.
2. Today is obvious.
3. Steps are executable.
4. Closure is humane.
5. Proof is saved.
6. Plan is believable.
7. Trust is visible.

---

## Strategic Non-Goals For 3.0

Do not prioritize:

- cloud sync as a launch dependency
- social planning
- public sharing
- team collaboration
- full AI assistant UI
- advanced external integrations
- subscription/paywall design
- advanced analytics dashboards
- generic calendar parity

---

## Decision Rule

When choosing between two designs, prefer the one that:

1. makes the Golden Launch Loop clearer
2. reduces top-level density
3. increases trust and correction
4. makes recovery easier
5. uses plain human language
6. preserves Ambitions' unique feel
