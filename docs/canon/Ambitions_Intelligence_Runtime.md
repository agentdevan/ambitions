# Ambitions Intelligence Runtime

Status: Active planned canon overlay; docs-only; not implemented by this document.

## Purpose

Ambitions Intelligence Runtime (AIR) preserves the local-only intelligence inventions that make Ambitions feel like a personal execution intelligence without turning the product into a chatbot, hosted AI wrapper, generic assistant, or hidden profiling system.

AIR exists to keep future implementation work specific, typed, inspectable, receipt-backed, privacy-gated, and user-correctable as it folds into existing PK, AOS, LDI, AFI, HPS, and Source Atlas owners.

## What AIR Is

AIR is the proprietary local-only intelligence scope for AmbitionsOS.

AIR turns user input, time reality, goals, commitments, proof, corrections, receipts, source state, and personal patterns into typed, reviewable, Ambitions-native behavior.

AIR intelligence must always be:

- local-first
- typed
- inspectable
- receipt-backed
- user-correctable
- user-resettable
- deterministic-fallback capable
- privacy-gated
- source-gated where relevant
- non-chatbot
- non-generative except for tightly bounded UI labels backed by typed state

## What AIR Is Not

AIR is not a chatbot, hosted AI wrapper, cloud LLM dependency, general LLM clone, writing assistant, email/text/message drafter, coach persona, simulated person, therapist, legal advisor, financial advisor, medical advisor, or hidden profiling system.

AIR does not authorize runtime behavior by itself and does not mark AmbitionsOS intelligence complete.

## Current IA Lock

The active top-level IA is:

```text
Today / Goals / Capture / Time / You
```

Plan is superseded as a top-level destination. Plan remains valid only as an action/contextual noun, historical evidence, or internal compatibility seam.

AIR must not add a sixth top-level tab, restore Plan as top-level, or convert Time into a calendar clone, agenda, or dashboard.

## Proprietary Native AI Thesis

AmbitionsOS is not a local GPT clone. AmbitionsOS is a proprietary local intelligence runtime that creates a GPT-like understanding effect inside Ambitions' domain through typed interpretation, bounded clarification, Life Graph context, Time context, proof, receipts, correction, visible assumptions, and deterministic fallback.

## Personal Runtime Thesis

Every Ambitions installation should become a private local user-specific operating instance. It learns from explicit preferences, schedule reality, goal structure, completion behavior, closure patterns, correction history, interaction timing, and user-reviewed assumptions. Personalization must affect recommendations, timing, density, language, recovery behavior, and surface emphasis, not only theme or greeting text.

The product bar is:

- A new user should feel: this app understands what I'm trying to manage.
- A 30-day user should feel: this app has learned how I actually operate.
- A 6-month user should feel: this instance of Ambitions would feel wrong if someone else opened it.

## No-Chat Law

AIR must never create a chatbot UI, arbitrary assistant prompt/response surface, avatar persona, simulated companion, or chat-first capture path.

Allowed assistant-like actions are bounded product verbs: clarify, place, review, why this, correct, close, reflow, remember, forget, and source needed.

## No-Hosted-AI Law

AIR must not depend on hosted AI, remote model inference, cloud LLM APIs, user-data servers, telemetry, analytics, or network availability for core behavior.

Any optional future model-assisted path must preserve model unavailable, model optional, deterministic equivalent, review required, and blocked model-required states.

## No-Message-Drafting Law

AIR explicitly forbids:

- writing texts
- writing emails
- drafting messages
- persuasive communication
- roleplay as a communicator
- turning a task into a message

Ambitions may clarify that a user intends to contact someone, place it as a step, schedule it, connect it to a goal, and track closure. Ambitions must not write the communication.

## Deterministic Fallback Law

Every AIR path must have a deterministic fallback or an explicit blocked state. Model output, semantic similarity, local classifiers, or optional device features may never be the only path to core Ambitions behavior.

## User Review, Receipt, and Correction Law

AIR may propose, classify, clarify, recommend, or quarantine. Consequential mutation requires user review and receipt. User corrections must be visible, reviewable, reversible, and able to improve future routing only through user-owned assumptions, rules, and receipts.

Hidden learning is forbidden.

## Privacy, Source, and Sensitive Area Law

AIR must preserve local-first privacy, private-source redaction, source-needed fallback, stale-source blocking, sensitive-area review, and professional-boundary limits.

Money, health, relationship, school, legal/civic, work, identity, and safety/crisis contexts require stricter handling and must not become professional advice or crisis-service behavior.

## Five-Surface Personalization Law

AIR personalization must work across Today, Goals, Capture, Time, and You without creating new top-level navigation.

The required user-facing personalization inventions are:

- Personal Runtime Signature
- Instance-Aware Today Greeting
- Clarification Micro-Conversations
- Assumption Ledger
- Local Learning Without Hidden Learning
- Five-Surface Personalization across Today, Goals, Capture, Time, You
