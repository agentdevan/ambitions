# Ambitions 4.0 Transformative Motion System

Status: Historical supporting canon; subordinate to `docs/truth/*`
Date: 2026-05-03

## Principle

Motion should transform state, not decorate state.

Motion is allowed when it helps the user understand continuity, ownership,
placement, receipt, proof, recovery, focus, or trust. Motion is not allowed as
spectacle.

## Required Motion Primitives

1. CaptureToReceiptMorph
2. HeroToSessionExpansion
3. RailRowToStepDetailTransition
4. PlanBlockToTodayTransition
5. GoalLaneFocusTransition
6. EvidenceToRecallBloom
7. ReceiptStackSettle
8. OverloadToRecoveryCollapse
9. ProofPulseSettle
10. QuietCommandFocus

Each primitive must define purpose, visual anatomy, source state, destination
state, allowed surfaces, forbidden surfaces, Reduce Motion equivalent,
VoiceOver behavior, Dynamic Type consideration, preview requirement,
performance risk, and validation requirement.

## Forbidden Motion

- infinite decorative motion;
- spinning or vortex effects;
- depth-heavy effects without Reduce Motion fallback;
- motion that delays task completion;
- motion that harms readability;
- motion without state meaning.

## Claim Boundaries

This document defines future motion direction. It does not claim current app
implementation unless a named batch, source file, preview, and validation
report prove it.
