Active Ambitions 2.0 UX writing truth now lives in [Ambitions_Design_Constitution.md](Ambitions_Design_Constitution.md) and [ux-writing-state-language-matrix.md](ux-writing-state-language-matrix.md). If this file conflicts with the active constitution, the constitution wins.

## Tone Rules

The product voice must be:

- calm
- clear
- respectful
- adult
- emotionally safe
- concise

## Approved Language Style

- "Still possible, but tighter than before."
- "A lighter version would fit better."
- "This looks based on older context."
- "One safe next move is still available."
- "This week may need more room."

## Disallowed Language Style

- hype language
- guilt framing
- startup-operator jargon
- technical AI self-reference
- childish reward language

Examples to avoid:

- crush it
- on fire
- streak in danger
- you failed
- model confidence: 0.72

## Empty State Rules

- state what this surface is for
- state the next useful action
- never feel like placeholder scaffolding

## Recovery Language

- recovery must feel relieving
- emphasize smaller safe movement
- avoid blame

Preferred patterns:

- "Today changed. Here is the lighter version."
- "You can protect this for later."
- "A smaller step still keeps momentum."

Recovery Bloom sequence:

1. show the safer path
2. state the calmer rationale
3. offer deeper explanation only on demand

## Trust Language

- explain without sounding technical
- prioritize plain language over diagnostic detail

### Trust Whisper examples

- "Based on your current week, this still fits."
- "This may need confirmation."
- "This changed after your last plan update."
- "The lighter path is more believable right now."

## Correction Language

- user is refining truth, not debugging a model
- preferred verbs:
  - update
  - change
  - use instead
  - clarify

## Momentum Language

- stabilizing
- building
- protecting
- recovering
- accelerating

## Continuity Ribbon Language

- carry one signal only
- use direct stateful phrasing

Examples:

- "Focus block still active"
- "This goal is tightening your week"
- "A newer correction changed this plan"

## Caution and Uncertainty Language

- likely
- may need confirmation
- based on older input
- not likely to hold at this pace

## Living Capture Language

- raw
- warming
- attached
- activated
- parked

Rules:

- capture-state language must feel like thought maturity, not ticket workflow
- avoid queue, assign, escalate, or other workplace vocabulary

## Quiet Command Sheet Language

- verbs must stay consumer-facing
- prefer:
  - capture
  - open
  - recover
  - explain
  - correct
  - focus

Avoid:

- execute
- dispatch
- invoke
- run command

## Sync and Trust Wording

- local-first by default when true
- Apple-account-based sync is launch direction, not generic cloud account copy
- no Ambitions account or in-app login should be implied at launch
- pending sync or stale state must be understandable in one line
- never expose raw system-state jargon as the first layer
- use the State Continuity Mesh contract in [../Ambitions_State_Continuity_Mesh.md](../Ambitions_State_Continuity_Mesh.md) for Now State Lease, Continuity Receipts, Sync Health Strip, semantic conflict language, and degraded-sync state wording

## Premium Restraint Rules

- keep copy short
- let hierarchy do the work
- one supporting sentence is better than three low-signal lines
- avoid tutorial paragraphs in default surface states
