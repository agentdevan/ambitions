## 6. Validation tracks

VC-13 executed six cumulative validation tracks.

### `VC13-STRESS-D01 — Expansion Without Loss`

Tests:

- accessibility Dynamic Type;
- Bold Text and Button Shapes;
- long canonical identities;
- long localized copy and actions;
- multiline chronology and state; and
- large focused review passages.

Locked rule:

> System-selected type size is preserved. Height and scrolling increase. Identity,
> current truth, applicable state, consequence, required action, and return are
> never removed to preserve ordinary viewport density.

### `VC13-STRESS-D02 — Nonvisual Semantic Continuity`

Tests:

- VoiceOver;
- Voice Control;
- Switch Control;
- Full Keyboard Access;
- hidden sensitive values;
- owner transfer; and
- failure, recovery, and settlement focus.

Locked rule:

> The nonvisual sequence preserves object identity, current truth, state,
> consequence, owner, action, and return without requiring spatial, color,
> material, or motion inference.

### `VC13-STRESS-D03 — Meaning Without Effects`

Tests:

- Reduce Transparency;
- Reduce Motion;
- Increased Contrast;
- Differentiate Without Color;
- grayscale; and
- low-brightness Dark appearance.

Locked rule:

> Every effect-bearing expression has an authored opaque, static, non-color,
> structural equivalent. Removing effects reduces atmosphere, not information.

### `VC13-STRESS-D04 — Density Without Dashboarding`

Tests:

- 30 or more Goals;
- many Life Areas;
- dense week chronology;
- long Today timeline;
- large Search result sets;
- dense settings states; and
- simultaneous resilience qualifications.

Locked rule:

> Repeated context, ownership, symbols, provenance, secondary chronology,
> preview breadth, and secondary relationships compress before identity, truth,
> state, consequence, action, conflict, or return. Natural scrolling and focused
> depth replace all-at-once compression.

### `VC13-STRESS-D05 — Combined Truth Under Failure`

Tests:

- offline plus stale external truth plus local editing;
- conflict plus over-capacity plus proposal;
- partial settlement;
- unavailable Undo;
- failed owner transfer;
- sensitive authentication failure; and
- local, section, root-wide, and global degradation.

Locked rule:

> Accepted truth remains authoritative. State is scoped to the narrowest truthful
> object or section. Only the highest-consequence state receives dominant
> articulation. Every unresolved condition retains an owned next action.

### `VC13-STRESS-D06 — Input, Direction, and Reach Transformation`

Tests:

- software and hardware keyboards;
- RTL;
- long localized actions;
- Voice Control and Switch Control;
- Full Keyboard Access;
- one-handed reach;
- safe-area pressure;
- system edge gestures; and
- focus entry and return.

Locked rule:

> Required actions remain reachable and named. Native directionality and focus
> remain authoritative. The dock adapts as one system and never becomes bottom
> tabs or a second accessibility navigation scheme.

## 7. Shared first-viewport doctrine

The stress program resolves first-viewport usefulness and accessibility
expansion through one cross-app rule:

> **Orient before the fold; complete through scrolling and focused depth.**

Every first viewport must establish, as applicable:

1. Place
2. Primary object
3. Current truth
4. Material state or consequence
5. One required action or direct entry into operation

It does not need to expose the full hierarchy, a complete timeline row, a full
Event, several Search results, every settings domain, or every stage of a
journey.

Ordinary viewport density is not protected at accessibility sizes.

## 8. Shared compression and preservation

Compress or move deeper in this order:

1. Repeated context
2. Repeated ownership
3. Decorative or secondary symbols
4. Supporting provenance
5. Secondary chronology
6. Preview breadth
7. Secondary relationships
8. Independently owned evidence and operations

Never compress away:

- Place
- Canonical identity
- Current accepted truth
- Applicable state
- Material consequence
- Required action
- Conflict
- Owner or source when authority depends on it
- Return

## 17. Keyboard-safe action boundary

A keyboard-safe action region is authorized only when:

- an active input exists;
- one progression action is required;
- native toolbar placement cannot remain reliably reachable;
- the active insertion point remains unobscured;
- the region disappears when the input posture ends; and
- it remains functional transient material rather than persistent root chrome.

This boundary applies to Capture progression and consequential or focused editing
where required. It does not authorize persistent floating actions in ordinary
Today, Goals, Time, or You browsing.

## 18. Non-color and reduced-effects contract

Every selected, proposed, protected, stale, conflict, failed, recovery, and
semantic state requires language, trait, and structure sufficient without color.

Every ordinary effect has an equivalent:

| Ordinary expression | Required equivalent |
| --- | --- |
| Blur or transparency | Opaque functional surface |
| Local relief | Rule, spacing, weight, tonal step, or label |
| Motion continuity | Static origin, state, and deterministic focus |
| Accent selection | Name, selected trait, and structural mark |
| Protected color field | `Protected` language and boundary |
| Proposed placement styling | Explicit `Proposed` heading and comparison |
| Conflict discontinuity | Participant identity and incompatibility language |

Violet-indigo remains an action accent and never becomes a semantic status or
root color.

## 19. RTL and semantic-order contract

RTL mirrors native interface direction. It does not reverse:

- earlier-to-later chronology;
- completed-to-active-to-planned progression;
- current-before-proposed truth;
- cause-before-consequence;
- root command order;
- Capture stage order;
- Search query-before-result meaning; or
- canonical ownership.

Spatial relationship geometry is removed when mirroring could imply false cause,
dependency, priority, chronology, or ownership.

## 20. Assistive-input contract

Required Full Keyboard Access order follows semantic ownership rather than
visual z-order:

1. Navigation and return
2. Current identity
3. Current truth
4. Material state
5. Primary content
6. Primary action
7. Secondary actions
8. Supporting evidence
9. Global navigation when active

Voice Control names must distinguish visible actions. Generic repeated `Open`,
`More`, `Button`, or `Item` labels are insufficient when several controls are
present.

Switch Control excludes decorative symbols, hidden dock controls, duplicate
selected elements, noninteractive rules, hidden sensitive values, and background
content beneath an active presentation.

Gestures remain supplementary. Every gesture-led action requires a named tap,
keyboard, or accessibility equivalent.

## 21. Focus entry and return contract

Focus entry:

- Root switch: restored object when valid, otherwise root identity
- Search: query field
- Capture: expression editor
- Focused Goal: Goal identity or restored progression position
- Focused Event: Event identity or restored field
- Settings depth: domain identity or restored control
- Review: review identity or current-truth heading
- Conflict: conflict qualification or first participant
- Failure: failure heading or primary recovery action
- Settlement: new authoritative result

Focus return follows truthful context:

1. Same object and posture
2. Same object in nearest stable posture
3. Same canonical owner
4. Same root and material section
5. Nearest stable root context

Search and Capture dismissal returns to the invoking command when nothing
changed, the originating object when valid, or the canonical owner when transfer
completed.

When exact restoration is unavailable, the interface returns to the nearest
stable owner and states what was not preserved when material.

## 22. Hidden sensitive-value contract

Before reveal, the accessibility hierarchy contains only:

- sensitive object identity;
- hidden state;
- authentication requirement; and
- Reveal action.

The hidden value is absent from speech, focus, previews, and active accessibility
content.

After successful reveal, the value enters only the revealed region. Rehide
removes it again. Failed or cancelled authentication preserves the hidden state
and returns focus to the failure heading or Reveal action.

Direct implementation proof remains required for app-switcher, notification,
backgrounding, and speech privacy.

## 23. Combined-state and announcement contract

Combined state reads:

1. Identity
2. Accepted truth
3. Truth qualification
4. Operational status
5. Consequence
6. Preserved capability
7. Required action
8. Owner or source
9. Settlement or return

Dominance follows:

1. Safety, privacy, or integrity restriction
2. Conflict
3. Mutation affecting accepted truth
4. Freshness, source, or verification limitation
5. Recoverable operational failure
6. Interaction posture
7. Supporting evidence

Announce consequential state changes as one restrained operation-specific
message. Do not repeatedly announce passive stale state, unchanged truth,
decorative progress, or every local status on root entry.

Exact timing remains a direct-device obligation.

## 24. Cross-app contradiction audit

The stress refinements remain mutually coherent.

### Root differentiation survives linearization

- Today: Start Here semantic passage
- Goals: Life Area → selected Goal → lens passage
- Time: period → chronological day/Event passage
- You: domain → current state → focused native control passage
- Capture: expression → interpretation → review passage
- Search: query → result or explanation passage
- Resilience: accepted truth → qualification → consequence → action passage

Vertical accessible geometry is shared; the primary object and semantic
progression remain distinct.

### Progressive disclosure preserves context

Content moves deeper only when identity, accepted truth, material state,
consequence, owner, required action, and return remain local or programmatically
recoverable.

### Calm and explicit state remain compatible

State stays at the narrowest truthful scope. Only one highest-consequence state
receives dominant articulation. Explicit accessibility language does not create a
warning console.

### Native behavior and flagship identity remain compatible

The system becomes more linear, opaque, labelled, and scroll-dependent under
pressure but retains the four roots, one dock, semantic hierarchy, canonical
identity, owner authority, matte plane, and root-specific purpose.

No contradiction requires a structural branch.
