## Purpose

This document turns Ambitions 3.0 into a FAANG-style rebuild documentation system for a solo-founder/Codex-driven product.

It defines how strategy, UX, visual design, content, iOS, data, AI, QA, privacy, accessibility, and product marketing work together.

---

## Operating Principle

Ambitions 3.0 is not built from raw idea banks.

Ambitions 3.0 is built from:

1. strategy
2. product language
3. primitives
4. state machines
5. implementation phases
6. evidence gates
7. Codex-only automated testing
8. release truth

## Required Work Sequence

1. Read source override.
2. Read parent index.
3. Read rebuild operating model.
4. Read primitive architecture.
5. Read language system.
6. Read target primitive/surface docs.
7. Implement scoped batch.
8. Run Codex-only evidence gates.
9. Update status truth.

---

## Documentation Completeness Standard

A major feature is not ready for Codex implementation until it has:

- strategy rationale
- user problem
- primitive mapping
- owner surface
- state model
- interaction model
- copy rules
- accessibility requirements
- privacy/trust requirements
- tests/previews
- release evidence expectation

---

## Ambitions 3.0 Build Thesis

Build in this order:

1. Core loop works.
2. Plan becomes mature.
3. Trust becomes inspectable.
4. Goals become deep.
5. Accessibility becomes resilient.
6. Shell becomes unique.
7. External surfaces extend safely.
8. Market story reflects only implemented truth.

---

## Acceptance Criteria

The rebuild operating model is working when every Codex batch can answer:

- which primitive is advanced?
- which loop step is advanced?
- what user problem is solved?
- what state machine changed?
- what copy changed?
- what tests prove it?
- what remains unimplemented?
