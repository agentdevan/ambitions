# Ambitions Full Front-End Transformation Program — Master UI Roadmap and Batch Plan

## Status

Active **post-hardening full transformation program** for Ambitions at the canon/control-file layer.

This document supersedes the narrower UI excellence wave framing. It assumes the user has explicitly approved:

- full Today / Goals / Plan redesign implementation
- full shell reconsideration
- full product logic expansion
- full external-surface implementation

It is designed to be used directly in the repo and by Codex in the same operational style as prior Ambitions planning docs.

## Current Roadmap Truth

This program does **not** rewrite the completed hardening wave.

Live queue truth in the current repo:

- Batch 38 — Completed

- Batch 45 — Completed

- the front-end transformation program is active in implementation at **Batch 46**

It makes the transformation program explicit enough to guide later implementation batches without authorizing shell implementation, route rewiring, or surface redesign work ahead of Batch 40.

## Program Rule

Nothing in the intended end-state is excluded from the overall program.

That does **not** mean every batch does everything.
It means every major surface, interaction system, shell change, logic expansion, novelty invention, external surface, and future-device surface is assigned somewhere in the batch sequence.

To preserve execution quality:

- use one active batch at a time
- work on `main`
- validate each batch before advancing
- defer items across batches when needed, but do not silently drop them from the program
- treat “deferred to later batch” as sequencing, not exclusion

## Signature Interaction and Visual Inventions

These inventions are part of the approved end-state and must be assigned across the program.

### 1. Living Hero Surface
A dynamic hero region on major surfaces that acts like the “current truth” layer of the screen.
Examples:
- Today = Now / Next / Recovery truth
- Goals = direction pressure / neglected goal truth
- Plan = week believability / room / overload truth
- Insights = narrative pattern summary
- Profile = trust / sync / personalization state

### 2. Contextual Global Compose
A persistent but restrained global affordance for:
- capture
- quick goal
- quick plan patch
- quick recovery
- quick focus
- fast search / memory recall

It should feel like part of the OS, not a floating social-media FAB.

### 3. Shell-Aware Transitions
Top-level and detail transitions share one motion grammar.
Examples:
- Today → Goal Detail
- Plan → Habit Planner
- Goal → Strategy Composer
- Notification / Widget → deep in-app landing

Transitions should clarify structural relationship, not merely animate.

### 4. Adaptive Header Rail
A unified shell header model that changes role by surface:
- execution
- direction
- shaping
- reflection
- trust / utility

### 5. Time Aperture
A premium way to inspect available time, block density, and room in the day or week without dropping into a dense calendar tool.

### 6. Recovery Bloom
A calming interaction pattern that appears when the day or week has drifted.
It reframes the state into:
- smallest safe next move
- lighter version
- reschedule
- protect later
- accept changed reality

### 7. Trust Whisper
A very light first-layer trust presentation system:
- “why this”
- “based on”
- “may need confirmation”
- “newer input available”

This should never feel like a debug console.

### 8. Pressure Scrubber
An interaction for Plan and Goals that lets the user scrub through week pressure, scope pressure, and timeline pressure with immediate visual feedback.

### 9. Path Filmstrip
A visual progression rail inside Goal Detail that makes ambition feel like a moving path instead of a database object.

### 10. Elastic Week View
A week-planning surface that expands and compresses density dynamically instead of forcing a static calendar grid.

### 11. Strategy Composer
A premium goal-setup and plan-shaping flow that feels like composing a believable strategy, not filling out a form.

### 12. Memory Lens
A global recall surface that lets the user pull up:
- recent corrections
- what changed
- why this goal looks this way
- what the app learned
- recent plan shifts
without going through an audit-log feeling flow.

### 13. Horizon Ladder
A zoomable structure from:
Ambition → Goal → Phase → Milestone → Step → Block → Today

### 14. Focus Screenlet
A compact focus experience for in-app use, Live Activities, widgets, and future Watch surfaces.

### 15. Appearance Studio
A premium personalization system for:
- dark / light / system
- curated accent families
- live preview
- ambient tone selection
- system material tuning
without turning Ambitions into a toy theme playground.

### 16. Sync Pulse
A calm, elegant cross-device trust indicator system for Profile and future device handoff points.

## Program Structure

### Wave A — Operating System Language
Build the shell, motion, global action model, design system, and cross-screen grammar.

### Wave B — Flagship Core Surfaces
Rebuild Today, Goals, Goal Detail, and Plan both visually and behaviorally.

### Wave C — Support, Reflection, and Trust
Rebuild Captures, Habits, Insights, Profile, onboarding, review, empty states, and cross-system trust surfaces.

### Wave D — External and Ambient System
Implement widgets, Live Activities, notifications, App Intents, share extension, and routing as premium first-class surfaces.

### Wave E — Future Surface Expansion
Implement iPad, Mac, Watch, and Apple TV continuity and first-platform realizations.

### Wave F — Finish Quality
Close motion, accessibility, performance, regression, and release-grade visual polish.
