---

## Purpose

This constitution prevents Ambitions from becoming a premium card pile.

Ambitions can be deep. Top-level surfaces must stay calm.

---

## Core Rule

Every top-level destination should show:

```text
1 signature object
1 primary action
1 contextual state strip
1 optional proof/trust/recovery prompt
Everything else drill-down
```

---

## Canonical Destinations

- Today
- Goals
- Capture
- Plan
- You

Each destination has one dominant signature object.

---

## Signature Object Ownership

| Destination | Signature object |
|---|---|
| Today | Reality Rail / AmbitionsDayRailView |
| Goals | Ambition Portfolio |
| Capture | Capture Composer |
| Plan | Plan Life Suite landing lens |
| You | Personal System Center |

---

## First Viewport Rule

The first viewport must answer the destination's primary question without scrolling.

| Destination | First viewport question |
|---|---|
| Today | What should I do now? |
| Goals | What am I moving toward? |
| Capture | What needs a place? |
| Plan | Does this hold together? |
| You | What controls Ambitions for me? |

---

## Top-Level Density Cap

Top-level screens should avoid more than:

- 1 dominant signature object
- 1 visible primary CTA
- 1 compact status/state strip
- 1 secondary section
- 1 optional prompt for recovery, proof, trust, or setup

If more is needed, route to a drill-down.

---

## Dashboard Creep Signals

A surface is drifting if it shows:

- multiple equal cards above the fold
- analytics before action
- more than two competing CTAs
- repeated status chips with no hierarchy
- separate panels for items that belong in one signature object
- unrelated reminders, proof, planning, and trust in one stack

---

## Allowed Top-Level Prompts

Allowed only when relevant:

- Close the loop
- Proof saved
- What needs a place?
- Schedule & Availability not set
- Plan needs a decision
- Recovery suggested
- Memory needs review

Only one should dominate at a time.

---

## Drill-Down Rule

Deep functionality belongs in drill-downs, sheets, or full screens:

- Step Detail
- Step Session
- Goal Detail
- Plan rooms
- Receipts & History
- What Ambitions Knows
- Reviews
- Automation & Trust

---

## Accessibility Rule

Reducing density is an accessibility requirement, not only a visual preference.

The first viewport should ask for no more than one meaningful decision.

---

## Acceptance Criteria

A top-level surface passes when:

- one signature object is dominant
- primary action is obvious
- first viewport is understandable without scrolling
- supporting information routes deeper
- no generic dashboard/card-wall feel
- recovery/trust/proof prompts do not compete
