# Ambitions 3.0 — Codex Value Maximization System

Status: Active Codex/product value guide

## Purpose

Codex should increase Ambitions value by reducing founder re-explanation, preserving source truth, accelerating implementation, and improving evidence quality.

## Value Levers

- Faster implementation: use context packs, skills, touch budgets, and focused validation instead of re-reading everything.
- Safer refactors: preserve compatibility routes, add tests before renames, and avoid parallel systems.
- Better documentation: keep 3.0 docs first, historical docs labeled, and reports evidence-based.
- Better test coverage: add domain/state-machine/projection tests near the changed seam.
- Better UI consistency: build through Ambitions 3.0 primitives, rails, nodes, sheets, receipt peeks, and signature objects.
- Better accessibility: write labels/hints as part of UI work and never claim manual verification without proof.
- Better privacy posture: keep local-first, visible consent, correction, receipt, export/import, and external-surface safety in scope.
- Better copy: use the Product Language System and copy guard; avoid AI theater, shame, fake scores, and generic productivity language.
- Better release evidence: maintain PASS/PARTIAL/FAIL gates and never upgrade posture without device/human/platform evidence.
- Better architecture: extend existing App/Domain/Services/Persistence/Features/UI/package boundaries.
- Better dependency discipline: document every tool and default to no new runtime dependencies.
- Better onboarding: make `.codex/README.md`, context packs, templates, and skill index the next engineer's map.
- Better investor/demo readiness: keep screenshot/readiness claims tied to actual UI and current simulator/device evidence.
- Better App Store truth: keep public claims blocked until support URLs, privacy labels, screenshots, signed archive, device QA, and accessibility proof exist.
- Better product/design/engineering continuity: route every build through strategy, primitive, state machine, UI, tests, and evidence.
- Better failure recovery: classify build/test/simulator failures and use playbooks instead of repeated blind retries.
- Better issue creation: reports should include exact next prompts and owner paths.
- Better PR review readiness: keep diffs scoped and include validation commands.
- Better QA evidence: keep xcresult paths, scan outputs, and known flakes documented.
- Better roadmap sequencing: use BATCH_REGISTRY for status and 3.0 F-series docs for next work.
- Better code ownership mapping: context packs name owned docs and code seams.
- Better state-machine maturity: prefer explicit Step/Capture/Placement/Closure/Proof/Memory/Recommendation transitions over ad hoc flags.
- Better proof/receipt/recommendation reliability: enforce the Evidence Hierarchy and Recommendation Eligibility Engine.
- Better external-surface safety: project only safe summaries; preserve manual confirmation and privacy labels.
- Better developer tooling without runtime pollution: use `gh`, `jq`, `xcbeautify`, `markdownlint-cli2`, and `lychee` for faster evidence, readable logs, and advisory doc QA while keeping Ambitions app runtime dependency-free.
