## One-Primary-Object Surface Law

Each top-level destination must keep one primary product object in front:

| Surface | Primary object | HPS inheritance |
| --- | --- | --- |
| Today | Start Here and Reality Rail | recommendation quality, commitment memory, privacy, proof, source freshness, no hidden mutation |
| Goals | Mission Control and path/proof spine | Human Progress Graph, Verified Proof Ledger, Source Truth, Option Value |
| Capture | placement and resolver flow | inferred-vs-confirmed memory, dream seriousness, correction receipts, no silent promotion |
| Plan | LifeShape and reflow decisions | capacity, commitment time, reality drift, privacy-safe external state |
| You | Personal System Center | memory permission, recall review, proof/export/delete/correction, trust controls |

HPS must stay underneath those objects. It must not become a new top-level
surface, analytics surface, generic command center, generic graph viewer, or
status pile.
