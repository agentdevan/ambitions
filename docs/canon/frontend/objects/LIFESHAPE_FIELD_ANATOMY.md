# LifeShape Field Anatomy

Status: Active primary-object canon
Destination: Time

## User-Facing Role

LifeShape Field shows capacity, protected time, pressure, reflow, and fit.

## Product Meaning

- capacity truth
- protected space
- pressure landscape
- before/after reflow

## Label-Off Visual Signature

- field-like layout, not a calendar grid
- protected space reads as carved negative space
- pressure reads as compression
- reflow appears as a before/after shape change

## Canonical Structure

- day surface
- week surface
- month surface
- protected time detail
- best-fit explanation
- reflow preview

## Visible Zones

- hard commitments
- protected blocks
- open capacity
- pressure clusters
- suggested fit

## Allowed States

- calm
- pressured
- protected
- open
- reflow preview
- stale source

## Forbidden States

- calendar clone
- event box grid as root model
- urgency dashboard
- alarm color system

## Primary Actions

- inspect fit
- protect time
- reflow preview
- confirm change

## Secondary Correction Paths

- adjust plan
- keep protected time
- undo
- recover from conflict

## Proof Behavior

Reflow and protected time should leave receipts and explain what changed.

## Receipt Behavior

Receipt output must stay tied to the time-shaping transaction.

## Source / Trust Behavior

Show source authority, freshness, and why another slot was not chosen.

## Local-Runtime Behavior

Local runtime can refine fit and pressure views, but it must not silently rearrange core commitments.

## Evolution Over Time

The field can become richer, but it must stay a capacity object, not a calendar clone.

## Failure States

- month view looks like a normal calendar grid
- reflow hides protected time
- pressure becomes color only
- source freshness disappears

## Recovery Behavior

- preserve protected time
- show a preview before commit
- keep the undo path visible
- explain the tradeoff

## ADHD Density Law

Show hard context first and keep the number of unresolved decisions low.

## VoiceOver Summary / Order

Object -> capacity -> protected time -> pressure -> reflow preview.

## Dynamic Type Behavior

Time labels and protected blocks must remain readable and scannable at large sizes.

## Reduce Motion Behavior

Use static before/after shape summaries rather than motion-only meaning.

## Reduce Transparency Behavior

Replace glass with readable opaque layers if needed.

## Increase Contrast Behavior

Strengthen boundary lines and protected-time separation.

## Differentiate Without Color Behavior

Use shape, spacing, and labels to distinguish protected, open, pressure, and stale source states.

## Native iPhone Believability Requirements

- feels like a native capacity field
- avoids calendar clone cues
- keeps fit/reflow decisions understandable

## Anti-Generic Red Flags

- calendar app
- event grid
- schedule dashboard
- alarm board

## Recipe Dependencies

- time root
- day lifeshape surface
- week lifeshape surface
- month lifeshape surface
- reflow preview tray
- best fit explanation sheet

## Source-Link Status

Linked through the live Time source candidates in `VISUAL_SOURCE_LINKS.yaml`.

## Good vs Bad Interpretation

- Good: "a capacity field where events are inputs, not the main object."
- Bad: "a prettier calendar."
