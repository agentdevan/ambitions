# Reflow Preview Tray

Status: Active frontend object bible
Kind: tray
Destination: Time

## What It Is

Reflow Preview Tray exists to provide time-specific preview-before-confirm, showing what changes and what stays protected. It is a source-linked tray for consequence preview, not a decorative module.

## Where It Appears

Primary location: Time. Cross-surface appearances must preserve origin, source, receipt/proof behavior, and return path.

## Hierarchy And User Job

Hierarchy level: tray. User job: understand current state, act with confidence, inspect source, and preserve proof or recovery without shame.

## State, Data, Proof, And Source

The tray must declare state in words and structure, not color alone. Source truth can come from live Swift source, local runtime/projectors, receipt/proof models, or source-family overlays that have been mapped to a real surface. Implementation is not claimed unless source evidence is mapped.

## Visual Tokens

Allowed token families: GraphiteRecess, QuietGlass, LuminousTrace, CelestialField, SF typography, semantic labels, restrained source/proof markers, and native controls.

## Interaction

Interactions must support inspect, preview, confirm, cancel, undo where appropriate, and receipt detail. Hidden gestures cannot be the only primary path.

## Accessibility

Dynamic Type keeps the object summary and primary action visible. VoiceOver exposes object summary, state, source, and available actions. Reduce Motion uses static state and before/after equivalents. ADHD usability requires one primary next action and no urgency mechanics.

## Must Never Be

Not a card-stack dashboard, chatbot, decorative space effect, score/streak/ring, sportsbook interaction, generic task row, or uninspectable recommendation.

## Proof Required

Future proof requires source mapping, screenshot/state proof, Dynamic Type, VoiceOver grouping notes, Reduce Motion, and receipt/proof path evidence before implementation or release claims.
