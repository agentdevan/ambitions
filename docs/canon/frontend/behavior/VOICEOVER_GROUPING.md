# Voiceover Grouping

Status: Active frontend behavior bible

## Rule

Voiceover Grouping exists to preserve object meaning, user control, and trust across Today, Goals, Capture, Time, You, shell, primitives, MRI, and HBI overlays.

## Required Behavior

- Communicate what changed and why.
- Provide visible source/proof/receipt path when meaning changes.
- Preserve cancel, confirm, undo, or manual fallback where appropriate.
- Avoid shame, urgency mechanics, fake precision, and hidden automation.

## Accessibility

Dynamic Type, VoiceOver, Reduce Motion, contrast, motor accessibility, and ADHD usability must remain equivalent to the visual path.

## Proof Required

Future implementation proof requires screenshots or walkthrough notes for default, empty, active, overloaded, recovery, blocked/waiting, no-data, large Dynamic Type, VoiceOver grouping, Reduce Motion, and iPhone size variants.
