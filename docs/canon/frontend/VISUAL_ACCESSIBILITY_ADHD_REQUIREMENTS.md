# Visual Accessibility And ADHD Requirements

Status: Active intended requirement set

These are recipe requirements, not implementation proof.

## Requirements

1. One dominant action at rest.
2. No more than three visible choices after capture.
3. No more than one unresolved warning or attention object per top-level surface.
4. Metadata collapses before actions collapse.
5. "Why this?" should fit in one screenful at first reveal.
6. Recovery mode reduces visible density by default.
7. "Needs a Place" is success, not failure.
8. No categorization is required before saving.
9. No shame copy.
10. Every state has a next safe action.
11. No color-only state meaning.
12. No motion-only state meaning.
13. No glow-only state meaning.
14. No tiny-only source/freshness indicators.
15. Primary actions remain reachable at large Dynamic Type.
16. VoiceOver reads object summary before child controls.
17. Reduce Motion replaces morphs with static before/after state.
18. Reduce Transparency replaces glass with opaque graphite layers.
19. Increase Contrast adds borders, seams, and stronger state separation.
20. Differentiate Without Color adds shape, icon, and text markers.
21. Hit targets stay native-believable.
22. Context switching is minimized after capture.
23. Destructive actions require preview.
24. Automation changes require clear consequence explanation.
25. Recovery flows keep the exit path visible.

## Required Behaviors

- Dynamic Type must preserve object summary, primary action, and recovery path.
- VoiceOver must announce object, state, source, proof, and action in that order when possible.
- Reduce Motion must keep meaning without relying on animation.
- Reduce Transparency must not hide state or source.
- ADHD density should shrink rather than multiply when overload appears.

## Proof Boundary

This file states intended requirements only. It does not prove accessibility conformance.
