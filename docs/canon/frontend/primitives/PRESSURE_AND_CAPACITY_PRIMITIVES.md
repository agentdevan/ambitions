# Pressure And Capacity Primitives

Status: Active primitive role set

## Protected Block

- carved-out time or space that must not be silently taken

## Purpose

Represent capacity, pressure, and protected time without calendar-clone language.

## Canonical Anatomy

- protected block
- pressure cluster
- current-state crown
- preview delta
- recovery basin

## Allowed Use

- show capacity
- show pressure
- show protected time

## Forbidden Use

- alarm language
- calendar clone cues
- pressure as shame

## Allowed Surfaces

- Time root
- day / week / month surfaces
- reflow preview

## Forbidden Surfaces

- generic urgency board
- task manager tile

## State Variants

- open
- protected
- pressured
- recovery
- overloaded

## Source / Proof / Receipt Behavior

Pressure and capacity changes should leave a preview and receipt.

## Accessibility Fallback

Pressure must be legible in shape and spacing, not alarm color alone.

## ADHD Safety Note

Show hard context first and keep one choice dominant.

## Pressure Cluster

- a visible compression of commitments or demand

## Current-State Crown

- the current-state header or orientation line for the surface

## Preview Delta

- before/after difference for a reflow or change

## Recovery Basin

- a low-pressure area for recovery and narrowing

## Holding Basin

- a safe holding area that is not shameful backlog

## Focus Narrowing Mask

- reduces visible density while preserving escape paths

## Capacity Confidence

- the system's confidence in available capacity, never a score

## Misuse Examples

- heat map without meaning
- calendar clone
- pressure tile with no recovery

## Recipe Examples

- protected time detail
- reflow preview tray
- best fit explanation sheet

## Validator Hooks

- pressure and capacity
- transaction coverage
- native believability
