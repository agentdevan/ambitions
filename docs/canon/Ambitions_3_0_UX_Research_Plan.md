## Purpose

This document defines the research protocols Ambitions 3.0 should use when human research is later introduced.

Current implementation may proceed Codex-only, but the repo should still document research intent and research questions.

---

## Research Thesis

Ambitions must be validated under real cognitive pressure.

The product is not successful merely because screens are beautiful. It is successful when users can capture, place, plan, act, recover, and trust what changed.

---

## Core Research Questions

1. Can a new user understand Ambitions in the first 60 seconds?
2. Can a user capture something meaningful without knowing where it belongs?
3. Does Placement Resolver feel helpful or controlling?
4. Does Today make the next step obvious?
5. Does Action Closure reduce shame compared with overdue tasks?
6. Does Still Counts feel credible and useful?
7. Does Plan Life Suite feel empowering instead of overwhelming?
8. Does What Ambitions Knows feel trustworthy, not creepy?
9. Does the unique shell remain understandable?
10. Does the app work for low-energy or ADHD-like planning friction?

---

## Core Study Protocols

### Study 1 — First 60 Seconds

Task:

- Open Ambitions.
- Capture one thing you want to organize.
- Place it or decide later.
- Explain what happened.

Success:

- user creates one useful object
- user understands destination
- user notices receipt
- no setup wall friction

### Study 2 — Today Start Here

Task:

- Open Today.
- Explain what Ambitions wants you to do.
- Open the recommended step.
- Start or adjust it.

Success:

- user identifies Start here
- user understands why it appears
- user can change it

### Study 3 — Broken Day / Closure

Task:

- A planned step did not happen as expected.
- Close the loop.
- Choose Still Counts, Rescheduled, Waiting, or Not needed.

Success:

- user does not interpret the flow as failure
- user understands proof/receipt outcome

### Study 4 — Plan Life Suite

Task:

- Review a busy week.
- Identify whether it holds.
- Resolve one decision or reflow one conflict.

Success:

- user understands Day/Week/Life Shape difference
- user sees open time is not automatically free time
- user trusts reflow preview

### Study 5 — Trust / Memory

Task:

- Open What Ambitions Knows.
- Review a memory source.
- Change, pause, or delete it.

Success:

- user understands what memory affects
- user feels in control

---

## Research Metrics

Qualitative:

- comprehension
- trust
- perceived control
- shame reduction
- clarity
- confidence in next step
- perceived usefulness

Behavioral:

- first useful object completion
- correct placement comprehension
- recommended step open/start
- closure completion
- Still Counts comprehension
- memory correction success

---

## Research Risks

- users interpret Ambitions as a task manager
- users distrust recommendations
- Plan feels too large
- shell feels unfamiliar
- Still Counts feels too vague
- proof feels like gamification
- memory feels creepy

---

## Acceptance Criteria

Research planning is complete when every major primitive has a validation question, task, success signal, and risk.
