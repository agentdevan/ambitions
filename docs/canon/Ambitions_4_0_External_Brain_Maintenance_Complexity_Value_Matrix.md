## Reason For Build Order

Trust and accessibility gates must precede durable memory and UI-heavy work. Onboarding should demonstrate value before advanced memory exposure. Universal Capture must precede memory ingestion. Life Memory Graph waits for source, confidence, deletion, correction, and receipts.

## Major Risks And Mitigation

- Privacy risk: require Trust Center, export/delete, audit trail, receipts, and release-claim scans.
- Cognitive-load risk: require density, plain-language, VoiceOver, Dynamic Type, Reduce Motion, non-color meaning, and overloaded-day evidence.
- Maintenance risk: keep owners narrow, use fixtures, avoid new dependencies, and require rollback.
- Product drift risk: keep Today / Goals / Capture / Plan / You locked and reject feature sprawl.

## What Not To Build First

Do not build durable memory, broad search, hidden personalization, automatic capture promotion, or advanced recommendations before Trust and accessibility gates.

## What Becomes Possible Later

After EB proof, Ambitions can support source-grounded recall, controlled memory, trustworthy capture routing, first-week setup value, accessible planning modes, and evidence-based recommendations.

## Staffing And Test Burden

The train requires product, privacy, accessibility, iOS architecture, QA evidence, and release-claim review. Tests must cover domain models, routing, receipts, privacy controls, accessibility behavior, fixtures/previews, import/export where touched, and regression safety.

## Expected Impact

External Brain is app-defining when implemented carefully. Trust impact is high if controls are visible and correction/deletion work. Cognitive-load risk is high if capture or memory becomes noisy. Integration risk is highest around existing Capture, You trust controls, recommendations, and persistence-adjacent future work.
