# LifeShape Field Visual Target

Status: Active positive visual target for Time / LifeShape Field
Scope: Time root first viewport and selected layer variants

The Time root must render as one dominant LifeShape Field instrument. It must not render as a vertical report stack, dashboard, card feed, calendar clone, or explanatory source panel.

Target family:

- dark graphite/OLED-native field
- one dominant circular or horizon-based time-capacity instrument
- open, protected, pressure, and buffer shown as visual layers or bands
- fixed points visible as marks on the field
- selected layer visible through color, shape, and semantic state
- current moment/now indicator integrated into the field
- one primary action inside or directly attached to the field
- horizon summary secondary to the field
- correction/detail UI hidden until user intent

Required first viewport hierarchy:

1. Shell-owned context crown, or explicitly crownless shell plus object-owned crown, but not both.
2. Dominant `time.life-shape-field.primary-object`.
3. Internal layer selector or segmented control, visually attached to the field.
4. Current layer/now readout inside the object, not as a separate report panel.
5. Fixed points and selected bucket marks inside the object.
6. One primary action.
7. Horizon/detail rows below the object only when there is room after the field has visual dominance.

Hard Red examples:

- duplicate shell/object crowns
- report panel primary object
- explanatory paragraph before the field
- semantic meaning rows as the primary field
- selected layer shown as a white slab unrelated to the field
- bucket detail or correction menu competing with the root object before user intent
- simulator screenshot path presented as visual acceptance
- no positive target comparison

Visual Green is not self-certifiable by Codex. Codex can move this work to Ready for Visual Review when target, actual, critique, and proof artifacts are present.
