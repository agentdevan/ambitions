# LifeShape Field Visual Target

Status: Active positive visual target for Time / LifeShape Field  
Scope: Time root first viewport, selected layer variants, and shell integration

The Time root must render as one dominant full-bleed LifeShape Field instrument. It must not render as a vertical report stack, dashboard, card feed, radial gauge, calendar clone, or explanatory source panel.

## Target family

- full-bleed dark graphite/OLED stage atmosphere
- shell and surface integrated into one native stage
- Context Crown floating inside the atmosphere, not a header slab
- Continuity Dock blended into the lower surface, not a pasted pill
- horizontal LifeShape Field Band, not a radial dial
- compact Weather-discipline readings, micro-bars, ticks, and horizon rows
- open, protected, pressure, and buffer shown as visual layers or bands
- fixed points visible as marks on the field
- selected usable window lifted inside the field
- current moment / now indicator integrated into the field
- one primary action attached to the selected window
- horizon summary secondary to the field
- correction/detail UI hidden until user intent

## Rejected direction

Do not use the radial dial as the North Star.

The primary Time object must not be a circular gauge, orbit ring, watch dial, or decorative arc chart. A small circular mark may appear only as a supporting micro-instrument when every segment maps directly to concrete Time semantics.

## Required first viewport hierarchy

1. Shell-owned full-bleed Context Crown, or explicitly crownless shell plus object-owned crown, but not both.
2. Compact layer rail visually embedded into the surface.
3. Dominant `time.life-shape-field.primary-object` as a horizontal / Weather-discipline field band.
4. Current layer reading inside the object, expressed as human reality copy.
5. Now marker, selected window, next fixed point, and protected boundary inside the object.
6. Selected bucket with time range, fit, and one action.
7. Horizon rows below the object only when there is room after the field has visual dominance.
8. Integrated Continuity Dock, visually subordinate and blended into the lower stage.

## Target root anatomy

```text
Full-bleed graphite/OLED stage
  Context Crown: Time / This week / Search / Capture
  Compact layer rail: Open / Protected / Pressure / Buffer
  Primary panel: Open capacity / One light window is open now / Next fixed point
  LifeShape Field Band: now marker / open windows / fixed-point ticks / protected boundaries
  Selected bucket: 10:40-11:10 / Usable light window / 30m before Team sync / Place step
  Horizon rows: Today / Tomorrow / This week / Rest of month with compact instrument marks
  Integrated Continuity Dock: Today / Goals / Time / You
```

## Approved copy direction

Use human reality copy:

- One light window is open now.
- One focused window before 10:00.
- No fixed blocks have been added yet.
- This week is still mostly open.
- Afternoon gets tight after Team sync.
- Protected until 2:00 PM.
- Needs buffer after 5:00 PM.

Avoid system-state copy such as `open layer`, route context, source context, preserved context, invented terrain labels, or capacity claims produced from fallback minimums.

## Full-bleed shell target

The shell is not a border around Time. The shell is part of the Time surface.

- no hard header slab
- no visible shell/content divider
- no pasted dock pill
- no giant selected layer slab
- no heavy container around the primary field
- no large bordered card around the entire Time object
- no content hidden by crown or dock

## Hard Red examples

- duplicate shell/object crowns
- report panel primary object
- explanatory paragraph before the field
- semantic meaning rows as the primary field
- radial gauge as the main object
- selected layer shown as a white slab unrelated to the field
- bucket detail or correction menu competing with the root object before user intent
- shell header visually bordered off from the surface
- dock visually pasted onto the surface
- simulator screenshot path presented as visual acceptance
- no positive target comparison

Visual Green is not self-certifiable by Codex. Codex can move this work to Visual Review Ready when target, actual, critique, and proof artifacts are present.
