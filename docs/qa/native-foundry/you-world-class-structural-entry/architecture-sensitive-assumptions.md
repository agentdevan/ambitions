# Architecture-Sensitive Assumptions

These assumptions constrain structural evaluation. They are not implementation decisions or component requirements.

## Preference command integration

Current source includes a runtime-selected You preference adapter, but meaningful mutation remains recorded as unproven. Directions may show fixture state and supported control anatomy; they may not claim proven root-to-runtime settlement.

Invalidated by: a current proof registry establishing a different supported boundary, or removal of the adapter path.

## Personalization provenance

Canon requires eight truth states, but current shipping provenance coverage is incomplete. Any complete register is synthetic research evidence until every displayed state has source, identity, chronology, and removal semantics.

Invalidated by: a canonical provenance model with different state ownership or hierarchy.

## Accent authority mismatch

The selected target calls for a restrained violet-indigo default while current source contains an older accent enumeration. Directions treat violet-indigo as target visual authority, not an implemented token or migration plan.

Invalidated by: reconciled canon/source authority that selects a different approved accent contract.

## Permission authority

Calendar, Reminders, and Notifications have source-backed permission posture. Local authentication is contextual. Other permission domains remain absent.

Invalidated by: new shipping permission adapters plus route and proof evidence.

## System Settings return

A source-purpose row may route to System Settings only when iOS owns the change. Exact app restoration and refreshed state require native proof.

Invalidated by: platform restrictions or an app-owned permission contract.

## Local-data statement

“On this iPhone · No Ambitions account” is valid flagship posture. It must not imply that every operating-system backup, device migration, or external integration behavior is absent.

Invalidated by: an account, supported multi-device continuity, or a changed flagship storage constitution.

## Data-control commands

Types or adapters for delete/forget requests do not establish a supported You command. Visible destructive controls require route, authorization, persistence, settlement, recovery/receipt, and proof.

Invalidated by: complete production evidence for the specific command.

## Accessibility behavior

The required transformation is specified, but exact wrapping, focus restoration, VoiceOver phrasing, and switch-control order require measured native and device proof.

Invalidated by: device evidence revealing a different viable semantic composition.

## Shell posture

The Crowned Edge Dock remains provisional. Directions assume only a compact You crown and native safe-area behavior; no dock geometry or shared-shell token is frozen.

Invalidated by: later cross-root synthesis and accepted shell proof.
