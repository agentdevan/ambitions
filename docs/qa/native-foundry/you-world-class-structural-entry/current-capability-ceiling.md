# Current Capability Ceiling

## Method

The RP-06 You capability inventory was treated as the starting ledger and reconciled only with source changes introduced after its audited baseline. Support was not inferred from filenames or type names.

## Supported or source-backed

- Local preferences for name, default root, review cadence, appearance, and action accent have source-backed models and persistence paths.
- System, Light, and Dark appearance selection are represented.
- Calendar, Reminders, and Notifications permission state have source-backed adapters or services.
- Local authentication exists where a supported operation invokes it; it is not a general account/security center.
- Version and build information can support About Ambitions.
- Runtime-selected preference commands now have an adapter path, but the meaningful-mutation registry still records the relevant runtime adapter integration as unproven.

## Partial or proof-limited

- Preference mutation has more source support than the RP-06 snapshot, but root-to-runtime integration and user-visible settlement remain unproven.
- Local-data summaries can describe the current local/no-account posture, but complete backup, restore, export, delete, and reset control is not present.
- Personalization provenance has a target vocabulary, but a complete shipping provenance history across all eight states is not established.
- Accessibility intent is specified, but the You root and bounded depths do not have current physical-device proof.
- The approved target calls for a restrained violet-indigo default, while current appearance/accent enums reflect an older accent inventory. This is an architecture-sensitive target/source mismatch, not permission to change tokens or enums.

## Absent or target-only

- Ambitions account, sign in, recovery, cloud sync, device management, subscription, sign out, and account deletion
- complete backup and restore
- broad export, delete-all, reset-all, or source-removal commands
- arbitrary permission inventory beyond currently supported integrations
- full personalization provenance editing and history settlement
- cross-device appearance sync
- typography, density, material, or motion editors
- production diagnostics console
- production Receipt and Undo coverage for every You mutation

## Command posture

An unsupported action is absent. A synthetic research state may be described as fixture-only. Inspection may expose truthful current state without implying a working command. Destructive request types found in source do not become supported You controls until a visible route, runtime selection, settlement, persistence, and proof all exist.

## Calibration ceiling

The first You calibration may use an immutable synthetic fixture to compare hierarchy, state semantics, and navigation. It must not imply that unsupported data-control commands, accounts, cloud services, or provenance mutation are shipping.
