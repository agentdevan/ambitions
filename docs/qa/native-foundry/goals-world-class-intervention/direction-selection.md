## Rendering scope

- one standalone full-screen Goals root per selected direction;
- identical fixture, device, dark appearance, standard Dynamic Type, and content density;
- no collage;
- no focused depth, Path, relationship, or accessibility frames until the owner selects one or two surviving roots.

## Protected characteristics

- persistent Life Area ownership;
- stable canonical Goal identity;
- current accepted truth as the second landmark;
- qualitative rather than quantified progression;
- Proof attached to the truth it supports;
- future certainty decreases with distance;
- intrinsic Linked Goal Lens;
- consequence before relationship metadata;
- native navigation and truthful return;
- no Today-specific composition.

## Questions to resolve

- Does D02 read as semantic continuity rather than time or percentage?
- Does D04 read as one persistent object rather than a custom card?
- Does D06 feel inevitable and native rather than like an accordion or effect?
- Which direction communicates the most before its copy is read?
- Which direction can generate root, focused Goal, Path, relationship, recovery, and closure without changing visual grammar?

## Immediate rejection conditions

Reject a rendering if it contains:

- giant repeated Goal titles;
- violet edge-rule panels;
- generic cards;
- section-document anatomy;
- project steppers or roadmaps;
- Proof checklists;
- equal jump buttons;
- graph connectors;
- architecture terminology;
- dashboards;
- decorative spatial infographics;
- copy carrying all hierarchy; or
- custom shell spectacle competing with Goals.

This decision does not select a final Goals direction, authorize SwiftUI implementation, authorize runtime integration, authorize production screenshot baselines, or set `APPROVED FOR SWIFTUI` to true.
