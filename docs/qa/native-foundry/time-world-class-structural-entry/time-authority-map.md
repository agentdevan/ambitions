## Required temporal truth

| Truth | Required meaning | Presentation consequence |
|---|---|---|
| Accepted placement | Time-owner commit relating one subject to one exact interval/window | May occupy accepted chronology; preserves placement and subject IDs. |
| Proposed placement | Simulated or suggested time, including computed Goal timing | Never receives accepted fill, language, trait, or accessibility state. |
| Accepted Ambitions Event | Ambitions-owned time-range commitment with stable Event identity | Distinct from a Step, Reminder, external item, or placement copy. |
| External observation | Named source fact, possibly capacity-relevant | Retains source and freshness; is not an Ambitions Event or accepted placement. |
| Stale external truth | Prior source observation beyond its freshness rule | Remains visible only with explicit stale/unverified qualification where material. |
| Historical chronology | Former accepted fact retained for inspection | Cannot masquerade as current or editable truth. |
| Unknown current truth | Current source or operation state cannot be established | Says unknown/unverified; does not infer success or emptiness. |
| Pending outbound change | Durable local operation with a real pending-operation contract | Absent unless stable operation identity, persistence, recovery, and reconciliation exist. |

Current accepted truth remains authoritative through preview, saving, failure, recovery, and cancellation. A proposal does not displace it until truthful settlement.

## Object and relationship ownership

### Event

An Event is a fixed-by-default, duration-bearing commitment with stable local, series, occurrence, source, recurrence, attendee, location, alert, time-zone, edit-authority, and Schedule Placement identity. It is not completable work. An Apple Calendar observation becomes an Ambitions Event only through explicit import/reconciliation.

### Schedule Placement

A Schedule Placement is the stable relationship between one capacity-bearing subject and Time. It contains range/window, zone, authority, source, protection/flexibility, fit assumptions, expected revisions, conflicts, history, and reflow rule. It does not copy or convert the subject. Computed Goal timing remains proposed until Time commits the relationship.

### Step

A Step is executable work. It consumes capacity only through an accepted Schedule Placement. Future Step is the same Step identity in a future role, not a second object. Its Goal/Path meaning remains Goals-owned even when Time projects the placement.

### Reminder

A Reminder is notification intent. Its trigger is not a duration or Schedule Placement and consumes no capacity independently. It may link to work or an Event without taking their authority.

### Recurrence and occurrence

Recurrence is type-specific: repeatable Step series, Event series with exceptions, or Reminder repetition. Mutations declare occurrence-only, this-and-following, entire-series, or selected-import-range scope and retain unaffected occurrence lineage.

### Source Reference

A Source Reference records provenance and freshness. It survives staleness and external unavailability without granting the external system private-graph authority or overwriting accepted local truth.

### Receipt and Undo

Receipt is a durable mutation result, not user Proof. Preview, selection, navigation, refresh, and cancellation create no Receipt. Undo is visible only while a real typed inverse or compensating command is eligible; a prior value or rollback ID alone is insufficient.

## Protection, fit, and conflict

- **Protected:** not violated by default; meaning and boundary must survive without color.
- **Fixed:** requires scoped override; default Event posture.
- **Flexible:** moves only within an explicit rule.
- **Suggested:** is not committed capacity.
- **Open:** describes calendar space only. It does not establish personal usability or recommend work.
- **Personally usable:** requires sufficient canonical availability, transition, constraint, and preference evidence.
- **Over-capacity:** aggregate demand exceeds usable capacity; it is not automatically a conflict.
- **Conflict:** identifiable valid participants cannot coexist. Review names participants, owners, incompatibility, consequence, protected meaning, and resolution authority without declaring a winner.

## Route and journey ownership

```text
Time root / active period
→ focused day
→ focused temporal object
→ current-versus-proposed review
→ truthful settlement or cancellation
→ originating period, day, object, and focus
```

- The root uses one Time-owned selected range and root-local selection/restoration state.
- Normal depth uses framework `NavigationStack`, native Back, and interactive Back.
- Compact object detail is used when bounded identity and inspection are sufficient.
- Consequential recurrence, grouped reflow, import, or current/proposed comparison uses focused review.
- No top-level Time sub-tabs, conflict/capacity/availability/reflow roots, AI-planning destination, or parallel calendar navigation are authorized.
- View switching is subordinate native chrome, not the first viewport’s product identity.

## Accessibility law

- Orient before the fold; complete through scrolling and focused depth.
- Preserve place, identity, accepted truth, state, consequence, action, authority where material, conflict, and return.
- Compact calendar geometry transforms to an ordered chronological passage or List.
- Current and proposed become explicit static sections.
- Every gesture has a named tap, keyboard, or accessibility equivalent.
- Protection, proposal, external source, freshness, conflict, and selection require language, trait, and structure beyond color.
- Reduce Motion uses static origin/current/proposed relationships and deterministic focus.
- Reduce Transparency uses opaque semantic surfaces.
- Increased Contrast strengthens text, rules, markers, and focus without altering meaning.
- RTL mirrors interface direction but does not reverse chronology, current-before-proposed order, cause/consequence, or ownership.
