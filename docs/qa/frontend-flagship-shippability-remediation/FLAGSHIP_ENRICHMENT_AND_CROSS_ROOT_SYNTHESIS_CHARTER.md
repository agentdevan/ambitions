# Flagship Enrichment and Cross-Root Synthesis Charter

Status: `QUEUED_AFTER_CAPTURE / PROVISIONAL_VISUAL_EXPLORATION / PRODUCTION_RECONSTRUCTION_BLOCKED`

Entry gate: accepted and synchronized Capture closeout.

Exit does not authorize production implementation or `APPROVED_FOR_SWIFTUI`.

## Purpose

Accepted Foundry work has established credible:

- native structure;
- interaction;
- canonical ownership;
- navigation;
- keyboard and focus behavior;
- accessibility transformation;
- journey semantics.

This phase determines how the complete frontend becomes:

- more inviting;
- richer;
- more beautiful;
- more personal;
- more alive;
- more emotionally intelligent;
- more expensive and deliberate;
- more coherent across roots and global experiences.

This is not:

- a restart;
- a superficial restyle;
- a generic polish pass;
- an implementation packet;
- an invitation to decorative complexity;
- a production implementation phase;
- permission to discard accepted structure;
- permission to weaken native behavior, accessibility, truthful state,
  performance, privacy, or local-first boundaries.

The phase formally replaces the narrower planned phrase **Cross-Root
Synthesis**. It is a provisional visual and behavioral exploration phase that
prepares reconciliation. It does not itself establish a production design
system, component API, runtime owner, or cutover path.

FR-2 requires the following inputs. Capture is an input only after its active

- accepted Today calibration;

## Structural protections

Enrichment may deepen expression only while preserving the following protected
structure and native behavior.

| Protected area | Structural protections |
| --- | --- |
| Today | Today remains the canonical persistent root; object identity, inspectability, current/next/flexible distinctions, settlement, recovery, and Undo remain truthful; the first viewport may become richer without becoming a dashboard or architecture display. |
| Goals | Goals remains the canonical Area → Goal → Step route; detail ownership, Back behavior, object continuity, and Goal/Step identity remain stable; no duplicate goal authority or decorative constellation may replace inspection. |
| Time | Time retains truthful Event, Schedule Placement, capacity, and recovery distinctions; proposed, accepted, missed, and restored states remain legible; enrichment may not invent calendar ownership or fake scheduling. |
| You | You remains a local-first personal settings and capability surface, not an admin dashboard or account requirement; privacy, local data, appearance, support, and valid preferences remain discoverable; Capture remains contextual rather than a fifth root. |
| Search | Search remains a global local/private discovery and handoff experience with result provenance, state truth, and route ownership; it must coexist with Capture without becoming a second object or mutation authority. |
| Capture | Capture remains a first-class global full-screen composer/action, not a persistent root, dock tab, inbox, notes feed, chatbot, classifier, or detached draft pile; input, review, interpretation, clarification, acceptance, cancellation, and return remain explicit. |
| Four-root IA | Today, Goals, Time, and You remain the four persistent roots. Search remains a global utility and Capture remains a global composer. Motion is behavior and state, not a destination. |
| Native navigation, focus, keyboard, safe area, accessibility, and Back | Native navigation and Back semantics remain authoritative; focus restoration, keyboard avoidance, safe areas, Dynamic Type, VoiceOver order, and assistive-technology actions remain functional and meaningful. |

A materially different structure may be explored only as a new branch with a
new stable ID. It cannot replace an accepted direction without Devan.

## Required workstreams

### 1. Visual atmosphere

Evaluate the complete experience in Light and Dark, including graphite warmth,
contrast, temperature, quietness, invitation, and emotional presence. Separate
atmosphere from ornament. Test whether a surface feels calm, alive, personal,
and deliberate while keeping state, action, ownership, and hierarchy visible.
Record where atmosphere strengthens an object and where it merely decorates a
container.

### 2. Typography

Define typography semantics rather than a list of font sizes. Clarify roles for
identity, hierarchy, supporting context, action, status, recovery, and
long-form content. Evaluate normal and dense states, Light and Dark, Dynamic
Type, long copy, localization, and RTL. Preserve system behavior where it is
the strongest native decision, and ensure typography carries hierarchy without
requiring cards, badges, gradients, or oversized display treatment.

### 3. Object anatomy

Make the primary object inspectable and emotionally legible. Evaluate object
shape, identity, supporting facts, lineage, action surface, destination,
settlement, recovery, and return. Preserve object continuity across roots,
Search, Capture, detail routes, review, cancellation, and Undo. Cover the full
state family from empty through ready, active, dense, blocked, failed,
settled, cancelled, restored, and recovery/Undo states.

### 4. Material, shape, and depth

Use semantic material, proportion, shape, layering, and Articulated Relief to
make relationships and hierarchy legible. Articulated Relief must be authored
through object anatomy, controlled depth, edge behavior, and meaningful
interaction rather than generic floating cards. Liquid Glass is restricted to
functional Crowned Edge Dock or crown chrome where it improves navigation or
control; it is not a default surface treatment. Every translucent treatment
requires an authored opaque equivalent for Reduce Transparency and must remain
performant, legible, and accessible.

### 5. Chrome and global experiences

Reconcile the shell, Crowned Edge Dock, root switching, global presentation,
Search, Capture, keyboard, safe area, Back, and return behavior as one system.
Search and Capture must coexist without competing for root status, focus,
global origin, or object ownership. Evaluate one-handed reach, reachable
actions, edge gestures, dock viability, restoration, and full-screen composer
presentation. Chrome must support the product rather than announce its own
architecture.

### 6. Motion and haptics

Use coherent motion and haptics to communicate continuity, focus, settlement,
recovery, cancellation, return, and consequential review. Keep motion
purposeful, interruptible, and native-feeling. Define Reduce Motion fallbacks,
avoid decorative animation, and preserve state truth when motion is disabled
or interrupted. Haptics must confirm meaningful changes rather than compensate
for weak hierarchy or unclear copy.

### 7. Content and emotional expression

Use human product copy that explains what happened, what will happen, where an
object belongs, what remains local, and how to change or cancel it. Remove
internal Foundry language, proof-harness terms, runtime jargon, classifier
language, and implementation vocabulary from user-facing surfaces. Preserve
original words where meaning depends on them, and let clarification and
review feel respectful, private, and intelligent. Emotional richness must
come from relevance, continuity, recognition, and honest context rather than
personality theater or inflated claims.

### 8. Accessibility and adaptation

Evaluate Dynamic Type, VoiceOver, Increased Contrast, Reduce Transparency,
Reduce Motion, localization, RTL, keyboard, focus, safe area, and one-handed
use across all roots and global experiences. Include dense states, long text,
empty states, failure, recovery, and Undo. Accessibility may recompose
geometry but may not remove meaning or required actions. Adaptation must
preserve object identity, state distinctions, navigation, return, and the
ability to complete every required action.

## Working method

Use this order for FR-2:

1. Inventory protected characteristics and native-default decisions.
2. Separate stable decisions from architecture-sensitive assumptions.
3. Identify Apple behavior intentionally left native.
4. Compare all roots and globals together.
5. Identify inconsistencies, sterile areas, over-conservative treatment,
   duplication, and missed semantic richness.
6. Propose materially different text directions.
7. Stop for Devan’s selection.
8. Render only selected directions as separate full-screen viewports.
9. Preserve structural differences.
10. Revise through the existing revision contract.
11. Create a new direction ID for material composition changes.
12. Maintain the decision, rejection, assumption, and native-default record.

The exact number of enrichment directions is established by the FR-2 entry
packet; this charter does not prescribe it. Text directions precede rendering,
and rendering remains fixture-driven provisional evidence.

## Anti-goals

FR-2 must not become:

- a restart of accepted native calibration;
- a superficial restyle of isolated screenshots;
- a generic polish pass on one root;
- a replacement for Capture closeout;
- an implementation packet or production implementation;
- broad production wiring or runtime integration;
- a component-library or finalized API exercise;
- a reason to begin isolated root campaigns after Capture;
- an invitation to add decorative complexity;
- an invitation to use glass, cards, gradients, pills, rounding, metrics, or
  motion without semantic need;
- a reason to discard accepted structure, navigation, ownership, or native
  behavior;
- permission to create a fifth root, duplicate Search/Capture authority, or
  invent route, object, state, or mutation ownership;
- a Figma selection or Figma authority phase;
- `APPROVED_FOR_SWIFTUI` or any production-ready status;
- a claim that fixtures, previews, or screenshots prove production behavior;
- a way to hide sterile or unresolved areas behind atmosphere;
- a weakening of clarity, truthful state, performance, privacy, local-first
  behavior, keyboard behavior, safe areas, or accessibility.

Beauty may not be purchased by weakening clarity, truthful state, performance,
privacy, native behavior, or accessibility.

Premium quality must come from:

- hierarchy;
- anatomy;
- typography;
- proportion;
- semantic material;
- controlled density;
- coherent motion;
- spatial continuity;
- emotionally intelligent content.

## Exit criteria

FR-2 exits only when:

- all four roots, Search, Capture, and shell have been evaluated together;
- Devan has selected the enriched direction;
- required evidence and state coverage exist;
- shared visual and behavioral direction is recorded;
- protected characteristics and assumptions are complete;
- reconstruction handoff is complete;
- no unresolved contradiction prevents FR-3 reconciliation.

FR-2 exits to FR-3 reconciliation—not directly to implementation. FR-3 must
reconcile the selected direction with completed architecture, UX Blueprint,
navigation ownership, capability boundaries, current runtime reality,
flagship-reconstruction baseline, and accepted Foundry evidence before any
production contract can be proposed.

## Capture non-interruption and closeout handoff

Capture continues unchanged under its approved current scope. This charter and
the accompanying plan update do not modify Capture acceptance criteria or
implementation. The active Capture branch is not rebased or interrupted now.

When Capture reaches owner closeout, it must reconcile onto the updated `main`
before merge. Capture closeout must record the evidence, protected
characteristics, unresolved visual opportunities, and architecture-sensitive
assumptions needed as FR-2 inputs. After synchronized Capture closeout, the
next campaign is FR-2. Broad production wiring and isolated root campaigns
remain prohibited.

## Proof and authority boundary

This charter governs documentation-defined provisional exploration. It does not
authorize Xcode, Simulator, Swift tests, screenshot capture, production source
changes, production components, tokens, runtime wiring, legacy cutover, or
approval language. Foundry screenshots and fixture contracts remain
non-production baselines with their existing proof ceilings. Native defaults,
accepted structure, accessibility semantics, local-first behavior, and privacy
boundaries are protected characteristics, not optional visual inputs.
