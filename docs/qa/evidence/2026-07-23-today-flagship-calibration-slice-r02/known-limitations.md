# Known limitations

- Owner visual acceptance is undecided.
- Simulator frames and recordings are evaluation references, not production
  baselines or direct-device proof.
- Physical VoiceOver order/focus, Switch Control, Full Keyboard Access, Voice
  Control, reach, edge gestures, low-brightness Dark, motion/transparency
  settings, and multi-device safe areas remain open.
- Fixture timing does not prove runtime persistence, asynchronous behavior, or
  latency.
- `View history` proves subordinate disclosure and return behavior, not final
  Receipt/History architecture.
- No generic Undo appears because the exact inverse prerequisites are not fully
  represented.
- No `Other outcomes` affordance appears. The fixture does not already provide
  executable exact review paths for every alternative, and R02 did not invent
  them. Canonical outcomes are not removed by this absence.
- Returned-Today de-duplication is fixture projection behavior, not a global
  production law.
- The Arabic Saudi fixture is evaluation copy, not production localization,
  linguistic approval, or localization completeness.
- The intentional scroll proof retains the complete Start Here identity because
  this dense fixture reaches its natural lower limit before Start Here can
  disappear cleanly. No snapping or product scroll change was introduced.
- No live runtime, product app entry, legacy frontend, other root, persistence,
  stale/rejected server branch, or offline runtime behavior was implemented.
