# 16 — Truth, Authority, Proposal, Recovery, and Closure Language

## Semantic grammar

| Epistemic state | Meaning | Required presentation |
| --- | --- | --- |
| Accepted/current | Canonical owner value now | Primary explicit text/structure; stable identity |
| Inferred | Local interpretation with bounded confidence | Named as interpretation; inspectable source; no automatic mutation |
| Proposed | Simulation/suggestion not committed | Visually separated from accepted truth; Review/Change/Cancel |
| Recommendation | Suggested next choice | Rationale and owner route; never “done” styling |
| Pending/saving | Command submitted but unsettled | Preserve prior accepted truth; disable duplicate submit; show recoverable progress |
| External observation | Named source fact | Source/freshness; never styled as Ambitions-accepted placement |
| Stale | Previously known fact beyond freshness | Explicit stale label + narrow refresh/recovery |
| Conflict | Two incompatible truthful claims/constraints | Both sides identifiable; no silent winner |
| Failed/interrupted | Operation did not settle | Accepted truth remains; retry/edit/keep unresolved |
| Recovered | User/system completed a bounded repair | Result + Receipt/History when capability exists |
| Completed | Goal/Step outcome settled | Proof/closure and historical continuity; no gamification required |
| Ended | Goal intentionally ended without completion claim | Reason/history retained; distinct from completed |
| Historical | Former accepted state | Inspectable chronology; not presented as current |
| Future possibility | Adaptable path or schedule option | Soft boundary; no accepted styling |

## Visual carriers

Use ordered structure, explicit short labels, owner/source identity, symbols, and consequence text. Color and material are redundant reinforcement. Avoid confidence percentages in primary UI and avoid exposing ledgers/kernels/graphs as user-facing authority.

## Cross-root rule

A projection may show truth but not mutate it unless it owns the command. Search and Capture transfer; Today executes only registered narrow actions; Goals owns Goal/path; Time owns placement; You owns supported preferences through named owners.
