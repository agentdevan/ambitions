# 14 — Accessibility Transformation Architecture

## Transformation law

Accessibility variants preserve the same semantic object and consequence while changing composition. They are not zoomed screenshots and not simplified child modes.

## Required semantic sequence

1. Context/root identity
2. Focused object identity
3. Accepted/current truth
4. Material state or conflict
5. Consequence/next movement
6. Primary action
7. Secondary objects/context
8. Return/owner route

## Transformations

- **Dynamic Type:** change columns/rails to ordered vertical groups; permit scrolling; keep surrounding context in compact summaries rather than deleting it.
- **VoiceOver:** explicit headings, stable object IDs, state + consequence labels, custom actions only when native controls cannot express them, deterministic focus after mutation/dismissal.
- **Switch/Full Keyboard:** logical groups, visible focus, no hidden gesture-only command.
- **Voice Control:** visible unique names; avoid repeated unlabeled “Open.”
- **Reduce Motion:** opacity/state replacement or brief causal transitions; preserve origin/destination continuity.
- **Reduce Transparency:** authored opaque shell/transient equivalents; meaning unchanged.
- **Increased Contrast / Differentiate Without Color:** thicker/labeled structure, explicit truth text, noncolor symbols.
- **Button Shapes/Bold Text:** native affordance remains visible without layout break.
- **Reach:** root/global actions maintain 44-point targets and lower-reach viability; device proof required.

## Family gaps

- Shell: manual VoiceOver, edge gesture, lower reach, keyboard coexistence, and physical glass remain open.
- Today: complete final package missing; manual transformation audit cannot be closed.
- Time: selected adaptation frames exist; assistive-service and device proof remain open.
- Goals: R03 transformation must preserve layered context and must not default to Previous/Next context erasure.
- You/Search/Capture/Trust: Maximum Polish transformation evidence incomplete.

## Proof rule

Static AX/RTL renders prove layout intent only. Manual VoiceOver, Switch Control, Full Keyboard Access, Voice Control, device reach, and focus restoration remain separate required proof.
