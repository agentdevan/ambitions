# 04 — Rejection and Anti-Pattern Library

| Pattern | Definition | Evidence | Severity | Detection / remediation |
| --- | --- | --- | --- | --- |
| **Cognitive infantilization** | Complexity is removed until the product presents giant symbols, primitive blocks, and one obvious button. | Goals R02 | Critical | Kill at owner-fit gate; restore layered context through visual encoding, not prose. |
| **Specification stack** | A screen narrates its own model in paragraphs and repeated labels. | Goals R01 | High | Reduce copy role-by-role; retain information as object state, spatial relationship, and concise evidence. |
| **Dashboardification** | Independent cards/metrics fragment a living system into evaluative tiles. | Goals rejected hypotheses | High | Use one continuous owned field with subordinate lenses and routes. |
| **Command outranks truth** | A large action surface appears before enough identity/consequence. | Today F-R01/R02 rejection lineage; Goals R02 | High | Earn the action after identity, current truth, and consequence. |
| **Generic card taxonomy** | Every semantic unit receives the same rounded container. | Object-language rejected stack; audit | High | Use grouping, alignment, dividers, native rows, and continuous fields before containers. |
| **Prototype cleanliness** | A sparse, orderly composition lacks authored detail and product-specific relationships. | Time R01 rejection; Goals R02 | High | Require a signature relationship and full state depth before expensive proof. |
| **Material compensation** | Glass/gradient/relief is added to make weak information architecture feel premium. | Shell/dock early iterations | Medium | Fix ownership and geometry first; material only for functional transient/shell roles. |
| **State-color overload** | Color becomes the primary carrier of action, status, owner, and emotion. | Global audits | High | Separate action accent, semantic status, explicit language, symbol, and structure. |
| **Decorative constellation** | Spatial metaphor becomes ornamental, gesture-heavy, or inaccessible. | Goals rejected map/constellation | High | Keep relationship depth inline and owner-routed; avoid decorative maps. |
| **Serialized depth** | Every layer is presented as another long vertical section. | Goals R01 | Medium | Use focused lens, spatial continuity, compact summary, and progressive disclosure. |
| **Generic Apple mimicry** | System components are copied without Ambitions-specific object behavior. | Cross-program risk | High | Retain native mechanics but own the orchestration, truth, recovery, and continuity model. |
| **Proof halo** | Builds/tests/adaptation boards create confidence that the design itself is good. | Goals R02 | Critical | Separate desirability gate from technical proof ledger; proof never upgrades owner state. |

## Use

A future candidate must be screened before native implementation. Any Critical pattern ends the concept. Two High patterns require architecture revision rather than a polish pass. The library is diagnostic: it does not replace owner review or current canon.
