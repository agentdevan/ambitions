# 12 — State and Interaction Completeness

## Verdict

The corpus is broad in typical, dense, accessibility, and selected state examples but incomplete as a product-state system. The strongest fixture proof is concentrated in Shell and Time. Goals defines many lifecycle states but has no selected visual architecture. You and trust/recovery remain the largest Maximum Polish gaps.

## Highest-risk gaps

1. Process-death restoration and stale-target fallback across every root/global session.
2. Loading/read-failure/unavailable behavior without false empty states.
3. Permission and external-source limitation states in Time/Search/Capture.
4. Real empty Goals/Life Area and very-dense pursuit fixtures under R03.
5. Saving/settlement failure and retry without erasing accepted truth.
6. Destructive closure/archive/trash consequences and return focus.
7. Background/foreground interruption during Capture, owner handoff, and mutations.
8. You unsupported capability absence versus unavailable supported capability.
9. Cross-root conflict and typed partial outcomes.
10. Exact keyboard/dismissal/restoration across deep routes.

`STATE_MATRIX.csv` marks `defined`, `partial`, `gap`, `proven-fixture`, `ledger-approved`, and `rejected-candidates`. A defined state is not implementation proof.
