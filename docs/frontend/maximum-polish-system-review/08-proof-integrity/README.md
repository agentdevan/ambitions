# 08 — Evidence and Proof-Integrity Audit

## Proof taxonomy

| Class | Establishes | Does not establish |
| --- | --- | --- |
| Concept/design | coherent intended anatomy | native feasibility or quality in use |
| Static board | rendered composition and adaptation claim | interaction, focus, restoration, performance |
| Native Simulator | framework rendering/geometry on named simulator | physical optics, touch, edge competition, device performance |
| Automated interaction | deterministic tested paths in fixture/app target | full state space, manual usability, owner desirability |
| Accessibility transformation | intended reflow/noncolor structure | VoiceOver/Switch/Voice Control behavior on device |
| Localization/RTL | selected strings/layouts survive fixtures | catalog completeness and all locale conventions |
| Fixture-host proof | prototype behavior against fixture data | production data ownership, persistence, concurrency, migration |
| Production-runtime proof | real app source/runtime behavior | physical-device/manual quality unless separately tested |
| Physical-device/manual | actual touch, optics, system coexistence, assistive behavior | untested models/OS versions or production architecture by itself |
| Owner decision | visual direction selected/rejected | production correctness or release readiness |

## Overclaims to avoid

- “Production-development-grade” in package prose describes prototype/evidence rigor, not production runtime or production approval.
- P01–P15 pass/provisional status does not imply owner acceptance.
- A UI test passing cannot establish maturity, emotional resonance, or perceived intelligence.
- Simulator Liquid Glass cannot establish device optical quality.
- Static accessibility/RTL boards cannot establish assistive-service behavior.
