# 19 — Iteration Economics, Stop-Loss, and Usage Governance

## Diagnosis

Maximum Polish front-loaded expensive native construction, five-pass refinement, adaptation matrices, tests, and proof packaging before owner-fit was established. Goals R02 is the clearest waste case: the cheapest decisive evidence was the overview board, but the owner saw it after the expensive proof train.

## New stage gates

| Gate | Required evidence | Cost ceiling | Exit |
| --- | --- | --- | --- |
| 0. Authority | current owner/canon/status/source index | low | exact problem and protected qualities |
| 1. Concept kill | text anatomy + anti-pattern/falsification review | low | architecture worth seeing |
| 2. Owner-fit | one compact board/wire direction | low-medium | no hard fail; owner permits native candidate |
| 3. Native-worthiness | one typical native frame + build | medium | native composition materially supports concept |
| 4. Owner selection | representative native board | medium | explicit owner selection/revision/rejection |
| 5. Adaptation-worthiness | targeted dense/Light/AX/RTL risk frames | medium-high | architecture survives pressure |
| 6. Full proof | focused tests, complete matrix, evidence ledger | high | bounded provisional closure |
| 7. Device/production | hardware/manual/runtime/architecture | very high | later FR/release gates only |

## Stop-loss conditions

- Any owner-fit hard fail: kill concept; no native build.
- Two material revisions with the same architecture-level rejection: replace architecture.
- A pass that cannot state what protected quality improved: stop.
- A late change affecting hierarchy/ownership invalidates downstream adaptation proof; do not patch around it.
- More than two repair passes after owner selection requires an explicit cost/benefit decision.
- Missing source authority or contradictory canon blocks proof expansion.
- Sunk proof cost never counts as a reason to continue.

## Usage controls

- Build the source index once and cite paths; no repeated corpus scans.
- Give subagents narrow, non-overlapping evidence slices and centralize status/finding IDs.
- Use one representative state to validate concept; expand only after owner selection.
- Run full P01–P15 once per selected architecture, not every cosmetic variant.
- Separate design exploration thread from implementation/proof thread.
- Preserve a compact handoff after each owner decision so future sessions do not reacquire history.
