# 07 — Maximum Polish Process Failure Autopsy

## Failure chain

1. Goals R01 correctly modeled many product obligations but exposed them as text and stacked sections.
2. Owner feedback targeted verbosity and cognitive load.
3. The process translated “less reading” into a doctrine of “one object, one state, one action.”
4. R02 rebuilt every depth around extreme object isolation, deleting surrounding pursuit context and adult complexity.
5. Five compounding passes optimized the chosen architecture rather than challenging it.
6. P01–P15 gates checked ownership, buildability, testability, adaptation, and evidence completeness; none contained a decisive owner-fit or perceived-intelligence gate.
7. Build, UI tests, accessibility/localization renders, and proof packaging produced a proof halo.
8. The internal recommendation advanced R02 despite a visible product-quality failure.
9. Owner review performed the missing desirability gate after the expensive work had already occurred.

## Root causes

- **Feedback-to-law overreach:** local feedback became a universal architecture rule.
- **No protected-quality ledger:** R01’s richness/intelligence was not listed as something the repair must preserve.
- **Pass convergence bias:** later passes assumed concept validity and polished execution details.
- **Gate category error:** technical validity was treated as evidence of product quality.
- **Late owner-fit:** owner review happened after full native/adaptation proof.
- **Single-axis optimization:** cognitive load was reduced without tracking information richness, maturity, distinctiveness, or perceived intelligence.
- **No adversarial comparison:** R02 was not forced through a direct “adult flagship vs toy-like simplification” test.

## Revised operating rules

1. Every revision begins with **Protect / Correct / Do Not Preserve**; feedback may not erase protected qualities.
2. A candidate must pass the owner-fit hard-fail screen before native implementation.
3. Every concept carries paired measures: reading burden and informational richness; calmness and sophistication; nativeness and distinctiveness.
4. Pass 1 must include a falsification attempt: identify the strongest reason the architecture should be killed.
5. Passes 2–5 may not proceed until concept validity is explicitly recorded.
6. P01–P15 are technical/design completeness gates, not desirability gates.
7. Full adaptation proof begins only after one representative native frame survives owner review.
8. A rejected concept cannot be “saved” because proof cost is sunk.
9. Two consecutive architecture-level rejections trigger a fresh written architecture, not another cosmetic repair.
10. Internal recommendations must state the strongest unresolved owner-fit risk before recommending advancement.

## Structural defenses

- Add an Owner-Fit Gate before P01.
- Add a Protected-Quality Diff to every revision.
- Add an Information Value / Reading Burden review to P02.
- Add a Maturity and Perceived Intelligence review to P03.
- Add an anti-pattern scan before native build.
- Separate proof ledger from selection recommendation.
- Require a stop-loss record before every additional repair pass.
