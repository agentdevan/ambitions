# Batch 11 — Canon Batch 8 / Ritual OS

## Status

Completed

## Goal

Build Ritual OS on top of the existing planning, recovery, time-orchestration, and ambient foundations so Ambitions supports coherent repeat loops like morning setup, midday reset, evening close, and weekly reset without introducing a new product shell or speculative habit theater.

## In Scope

- audit current Today / Goals / Insights / notifications / snapshot seams for ritual entry points
- define the minimum computed ritual domain model needed now for morning setup, midday reset, evening close, and weekly reset
- add shared ritual orchestration/service logic using existing planning, recovery, evidence, capture, and time outputs
- surface ritual outputs through Today as the only primary app surface
- expose only privacy-safe ritual cues through existing snapshot, widget, and notification paths where useful
- add focused tests for ritual recommendation generation, state transitions, repeat-loop behavior, Today presentation, and snapshot compatibility

## Out Of Scope

- App Intents
- controls
- sync
- life graph / household / device work
- broad UI redesign
- a ritual screen, ritual tab, or new navigation flow
- new habit-tracker systems or Habits expansion
- speculative motivational/narrative features not backed by existing product seams
- new surface-local business logic in widgets/notifications
- major calendar intelligence beyond what already exists

## Dependency Rules

- do not skip ahead
- Ritual OS must consume existing planning, recovery, time, and ambient infrastructure
- no new parallel planner, review system, or habit engine
- keep ritual logic in shared services/domain models, not screens
- prefer small truthful ritual states over large abstract frameworks
- do not invent AI coach behavior disconnected from current repo capabilities

## Extra Constraints

- keep Ritual OS computed, not persisted; do not add new persistence entities or migration work unless a compile-critical need appears, and report that instead of expanding scope
- keep ritual outputs deterministic and compact
- reuse existing Today actions when follow-through is needed; do not create ritual-only action types unless strictly required
- ambient ritual cues must remain privacy-safe and must not include user-entered goal titles, capture text, notes, summaries, or detailed step text
- prefer additive optional fields in snapshot/contracts and preserve backward decode compatibility
- do not request calendar permission during passive Today load; use only already-available pressure/context signals conservatively
- mark Batch 11 completed only if generation, build, targeted tests, and full unit validation all pass
