# PXOS Definition Of Ready And Done

Status: Future Codex OS standard; PXOS implementation not started
Date: 2026-05-02

## Definition Of Ready

A PXOS implementation batch is not ready unless it has source truth, surface
ownership, product decision lock, affected screens/surfaces, allowed files,
forbidden files, ME dependency check, CS dependency check, AOS dependency check,
REC/release-claim check, accessibility expectations, copy/language expectations,
visual acceptance criteria, test plan, rollback plan, evidence output, and stop
conditions.

## Definition Of Done

A PXOS implementation batch is not done unless it leaves changed file list,
validation logs, screenshot/preview evidence if UI touched, product acceptance
evidence, accessibility evidence if UI touched, copy review evidence if copy
touched, release-claim scan if messaging touched, compatibility scan if routes
or external surfaces touched, maintainability scan if Swift touched, unresolved
Yellow list, next safe prompt, and rollback/repair path.
