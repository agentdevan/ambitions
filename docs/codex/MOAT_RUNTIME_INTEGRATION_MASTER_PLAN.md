## Purpose

Moat Runtime Integration exists to prevent Ambitions from becoming a set of completed components that still fails to behave like the end-game product.

The active product goal is not merely to complete batches. The goal is to make Ambitions operate as a premium local-first iPhone life operating system where private ambition context compounds into proof-backed execution decisions.

MRI converts the remaining train from component completion into loop completion.

## Governing Product Standard

Every post-MRI batch should answer:

```text
Does this close one of the end-to-end Ambitions loops, or did it only add another piece?
```

If it only adds a piece, the batch may still be useful, but it must state which loop it supports and what later batch closes the loop.

## Relationship To Existing Trains

MRI does not replace SA, AOS, LDI, FCP, PFC, RHC, or the visual/moat train.

MRI overlays them:

- SA provides source, claim, proof, freshness, importer, review, and pack infrastructure.
- AOS provides local operating intelligence and AmbitionsOS kernels.
- LDI provides long-range dream/life-direction compilation.
- FCP provides flagship product completion.
- PFC provides Apple/platform/release infrastructure.
- RHC cleans repo authority and obsolete material.
- Visual/moat runtime implements the native signature interface.
- Assurance Lab validates that all loops work.
