## Purpose

Ambitions cannot be proven by default-state fixtures. It must be proven against real life: overloaded days, forgotten promises, private commitments, stale sources, pivots, blocked goals, recovery, and Found Life context.

## Required Golden Scenarios

At minimum, scenario fixtures must cover:

1. Day job + baby preparation + relationship commitment + app project.
2. Overloaded day with a still-important goal.
3. Forgotten promise that should surface gently.
4. Private commitment that must not leak externally.
5. Stale source affecting a recommendation.
6. No schedule setup / low context user.
7. Missing duration / ambiguous step.
8. Blocked goal with recovery path.
9. Abandoned project revival.
10. Career pivot where prior progress still counts.
11. Music project + creative momentum + day job.
12. Trading/news interest with safety/no-professional-advice boundaries.
13. Weekly Life Sweep with multiple open loops.
14. Relationship/family priority conflict.
15. Work follow-up at risk.
16. Protected time conflict.
17. Recovery day after missed commitments.
18. Goal proof saved and receipt reviewed.
19. Capture item needs placement.
20. User rejects/corrects a remembered inference.

## Founder Scenario Pack

The founder scenario pack is a canonical high-pressure user fixture:

- 32-year-old ambitious user
- ADHD / high working-memory burden
- baby on the way
- relationship commitments
- day job/work obligations
- building Ambitions
- making music
- watching sports/news
- trading/stock news interest
- career growth / next tax bracket
- errands, birthdays, plans, promises
- tendency to start intensely and pivot
- desire to be found in life while enjoying today

This scenario must not overfit the app to one person, but it protects the core archetype.

## Use By Domain

- FVQ: screenshots must include scenario states, not only perfect default data.
- AXQ: Dynamic Type and VoiceOver must be tested against dense real states.
- PVQ: private scenario content must be tested against external surfaces.
- RIQ: recommendations must be tested against scenario capacity and source truth.
- DIQ: persistence/sync must preserve scenario state integrity.
- PERQ: performance must hold under realistic surface density.

## Failure Rules

Default-only proof is insufficient for any flagship object.

If a scenario fixture is missing, classify Yellow with owner unless the missing scenario is required to support the current batch claim; then classify Recoverable Red or Hard Red depending on risk.
