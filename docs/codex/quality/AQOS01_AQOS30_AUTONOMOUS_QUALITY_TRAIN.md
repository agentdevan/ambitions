Status: Active Codex OS quality train. Queued at the earliest safe batch boundary.
Date: 2026-05-05

## Required Approval Phrase

`Start AQOS Train`

The global rendered visual excellence overlay and global quality overlay may also select AQOS when the user has preauthorized cross-train execution.

## Purpose

AQOS makes every future Ambitions batch evidence-gated, adversarially reviewed, repair-capable, and flagship-bound.

## Placement

Run AQOS at the earliest safe point after the active Codex batch finishes. If FVQ is already queued or running, AQOS should not interrupt it. Preferred safe order:

1. Finish active batch.
2. Run FVQ01/FVQ02 if visual Hard Red risk exists.
3. Run AQOS01-AQOS30 source truth / scripts / skill / orchestrator integration.
4. Resume global order with AQOS required at every batch boundary.

## AQOS01 — Evidence-Gated Quality Canon

Create/lock the AQOS canon and no-matching-evidence-no-Green rule.

## AQOS02 — Batch Impact Classifier

Create a classifier that maps changed files/domains to required proof gates.

## AQOS03 — Required Evidence Matrix

Create matrix mapping domain touched to mandatory proof artifacts.

## AQOS04 — Green Taxonomy / No Generic Green

Require Structural/Behavioral/Visual/Accessibility/Privacy/Performance/Architecture/Release/Handoff Green labels.

## AQOS05 — Repair Batch Generator Protocol

Define automatic narrow repair-batch creation with owner, allowed files, forbidden files, proof, rollback, and stop conditions.

## AQOS06 — FVQ Integration Hardening

## AQOS07 — Five-Tab Visual Baseline

## AQOS08 — Screenshot Freshness Infrastructure

## AQOS09 — Accessibility Execution Quality

Require VoiceOver order, Dynamic Type, Reduce Motion, non-color meaning, touch targets, truncation, and privacy-safe accessibility labels.

## AQOS10 — User-Facing Copy Quality

Require human, non-shaming, non-internal, non-generic, source-aware, privacy-safe copy.

## AQOS11 — Privacy Exposure QA

Require leak checks for Found Life content in widgets, Live Activities, notifications, screenshots, logs, previews, App Intents, Spotlight, shared storage, analytics.

## AQOS12 — Sensitive Surface Leak Matrix

Map sensitive fields/surfaces/redaction policies and external-surface defaults.

## AQOS13 — Data Integrity QA

Require migration, deletion, export/import, corruption, backup/restore, stale data, offline/conflict/tombstone proof where applicable.

## AQOS14 — Performance / Battery Budget QA

Require launch, render, memory, animation, background, widget reload, Live Activity update, sync/persistence, low-power budgets.

## AQOS15 — Security / Secrets / Logging QA

Require secrets, logging, sensitive metadata, debug overlay, network/storage, and release-claim safety proof.

## AQOS16 — Architecture Fitness Tests

Require file-size, dependency, ownership, view/domain separation, duplicate model, fixture health, and no-junk-drawer checks.

## AQOS17 — Prompt-Built Smell 2.0

Strengthen scans for generic cards, manager/helper sprawl, placeholder residue, over-naming, fake intelligence, repeated boilerplate.

## AQOS18 — File Bloat / Ownership Drift Gate

Set thresholds and repair protocols for large SwiftUI files, unowned primitives, and feature-boundary leaks.

## AQOS19 — Handoff Cleanliness Gate

Ensure a senior external iOS team can understand repo organization without chat history.

## AQOS20 — Evidence Maturity Ledger

Track every object by Design Canon, Implementation, Visual Proof, Accessibility Proof, Privacy Proof, Performance Proof, Tests, Release Proof, Handoff Proof.

## AQOS21 — Recommendation Quality QA

Require AOS/LDI recommendation proof: source-grounded why, option value, capacity realism, correction loop, no fake certainty.

## AQOS22 — AOS / LDI Golden Scenario Harness

Create canonical scenarios for overloaded day, baby/family, career pivot, forgotten promise, stale source, private commitment, parked project revival, recovery day, weekly sweep.

## AQOS23 — External Surface Safety QA

Require widgets, Live Activities, notifications, App Intents, Spotlight, and external surfaces to be privacy-safe, source-aware, accessible, and non-noisy.

## AQOS24 — StoreKit / Monetization QA

Require entitlement, restore, cancel, family/plan state, paywall compliance, no dark patterns, App Review-safe claims.

## AQOS25 — App Store Claim Truth QA

Require claim-truth packets for screenshots, descriptions, privacy labels, required-reason APIs, release notes, TestFlight/App Store readiness claims.

## AQOS26 — Autonomous Red-Team Board

Run adversarial review across product, design, iOS, accessibility, privacy, security, performance, QA, App Store, founder vision, handoff.

## AQOS27 — Human Proof Bridge

Create exact checklists where Codex cannot self-certify: human visual review, physical device, legal review, public accessibility, App Store review.

## AQOS28 — Release / Handoff Evidence Packet

Aggregate evidence into final release/handoff proof packets with no unsupported claims.

## AQOS29 — Global Orchestrator Integration

Update orchestrator/registry/context/order to require impact classification and matching evidence at every batch boundary.

## AQOS30 — AQOS Closeout / No-Proof-No-Green Lock

Close AQOS by proving future batches cannot generic-Green without matching evidence.

## Hard Red

Stop if AQOS finds:

- fake evidence
- hidden hard Red
- unsupported release/legal/privacy/security claim
- sensitive data leak
- unproven data-loss risk
- rendered top-level visual prototype/dashboard failure after repair
- Codex would need to weaken canon or delete tests to pass

## Completion

AQOS completes only when source truth, prompts, skills, advisory scripts/specs, overlays, and global integration exist and future batches are required to use Evidence-Gated Quality.
