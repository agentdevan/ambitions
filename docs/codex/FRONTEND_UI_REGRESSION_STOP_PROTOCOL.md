Status: Active FET protocol
Date: 2026-05-09
Batch: FET11

## Purpose

UI regressions stop continuation when rendered evidence proves the product has become less clear, less native, less accessible, more generic, denser, or less aligned with Ambitions identity.

## Stops The Train

- Hard Red frontend condition appears in screenshots or preview evidence.
- UI-touching work has no rendered evidence.
- Visual QA score is Red.
- Bottom chrome conflict remains.
- Today still reads as a report/card stack after a Today recovery batch.
- Accessibility primary-action blocker appears.
- Route/raw/persistence/schema risk appears outside approved scope.
- A batch tries to use build/test success to override visual Red.

## Repair Loop

1. Identify exact surface, screenshot, file, and gate.
2. Repair by deleting, collapsing, constraining, or recomposing before adding.
3. Re-run focused validation and FET scans.
4. Re-capture visual evidence.
5. Re-score.
6. Continue only when Red clears or is explicitly parked Yellow by owner and not a hard Red.

## Screenshot Comparison

Compare baseline and after screenshots for first-glance clarity, bottom chrome ownership, density, copy, primary object, surface distinction, accessibility risk, and motion notes. Pixel-perfect equality is not required; product-quality regression classification is required.

## Inventory Guard

Future feature batches may add UI only after composition proof shows where the new capability lives, what was removed/collapsed, and why the first viewport remains within budget.
