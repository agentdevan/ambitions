## Purpose

This map ensures Human Progress Systems strengthens Ambitions without creating sprawl. HPS must govern remaining FCP, AOS, LDI, PFC, CQS, and FVQ work that touches life visibility, proof, source truth, recommendations, commitment memory, recall, option value, dream handling, AI/local intelligence, vertical strategy, privacy-sensitive memory, or acquisition-readiness strategy.

## PFC integration

PFC legal/privacy/security/performance/platform work must account for HPS risks.

Required references:

- PFC26 legal review packet must mention Human Progress Graph, Proof Ledger, Searchable Life Recall, vertical expansion, and local intelligence adapter risks.
- PFC27 safety/professional boundary must include dream handling, career/education recommendation, minor/student-data, and crisis boundaries.
- PFC28 security threat model must include sensitive memory, proof evidence, source packs, exports, logs, widgets, Live Activities, App Intents, notifications, and future sync.
- PFC29 observability must forbid private life text, proof contents, sensitive memory, and recommendation source details in logs/analytics.
- PFC30 performance budget must include graph traversal, recall, local model adapter, rendered proof, and high-pressure surfaces.
- Later PFC external-surface implementation must use private-by-default HPS redaction.

## FVQ integration

FVQ must require rendered proof for HPS-dependent visible surfaces. UI-affecting HPS-dependent work cannot close Green from docs/build/tests alone.

Required FVQ checks:

- one primary object per top-level surface
- no dashboard drift
- no generic card stack
- privacy-sensitive redaction state
- stale/source issue state
- recovery/blocked state
- overload/high-pressure state
- reduced-motion/nonvisual equivalent
- external surface proof when platform surfaces are touched

## Global order rule

Preferred order:

1. Finish active PFC26-PFC30 block if already running.
2. Run HPS01-HPS12.
3. Continue FCP22+ surface maturity.
4. Continue platform implementation.
5. Run AOS only after HPS inheritance.
6. Run LDI only after HPS inheritance.

If work has advanced past this point, insert HPS at the earliest safe remaining point and document accepted Yellow rather than replaying completed batches.
