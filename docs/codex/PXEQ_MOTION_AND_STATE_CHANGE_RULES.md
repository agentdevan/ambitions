# PXEQ Motion And State Change Rules

<!-- markdownlint-disable MD013 -->

Status: Active PXEQ motion rules.
Date: 2026-05-03

Motion must explain where the user is, what changed, what can be acted on, or
what is now resolved. Motion must not decorate, distract, gamify, hide loading,
or pretend intelligence. Every meaningful motion needs a Reduce Motion
equivalent. Living modules must name their state inputs, transitions, fallback
state, and user-control affordance.
