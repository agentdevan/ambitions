## Purpose

This file maps Ambitions Object OS systems to the app's top-level surfaces, drill-downs, chrome, native extensions, and proof surfaces.

Active top-level IA remains:

- Today
- Goals
- Capture
- Time
- You

No additional top-level tab is introduced by Object OS. Object OS is the product grammar beneath and across those surfaces.

## Drill-downs

### Universal Object Command Center

Any major object can open a shared detail architecture:

- identity/state
- why it matters
- proof
- source
- history
- available actions
- receipts
- trust
- correction
- undo
- native surface eligibility

### Action Slip Detail

Used before committing to action:

- candidate step
- Ambition / Goal Thread link
- time fit
- proof opportunity
- source basis
- risk if delayed
- closure options
- start / revise / dismiss

### Proof Vault Detail

Used for proof/receipt review:

- proof state
- source links
- attached commitments
- transfer history
- staleness / contradiction
- export/delete controls

### Recovery Thread Detail

Used for recovery-first execution:

- last honest point
- what changed
- what still counts
- preserved proof
- blocked dependencies
- smallest re-entry step
- recovery receipt

### Simulation Detail

Used before major changes:

- before/after state
- affected objects
- proof transfer
- risk
- undo availability
- confirmation action

### Personal Runtime Detail

Used to inspect local learning:

- learned signal
- source of learning
- last used
- recommendations affected
- disable/reset/delete/export
- learning receipt

### Source Trust Detail

Used for Source Atlas objects:

- source identity
- claims extracted
- proof attached
- freshness
- contradictions
- recommendations using it
- review/revoke/replace

## Today / Reality Meridian

Required object behavior:

- Start Here is the dominant daily object.
- Active Commitment can move into Continuity Dock.
- Reality Meridian shows current context, not a task list.
- Closure options are object states, not binary done/fail.
- Receipt Peek appears after meaningful action.
- Recovery Thread appears when the day breaks.
- Why Not Now can explain suppressed recommendations.

Key primitives:

- Start Here object
- Action Slip
- Active Commitment
- Closure controls
- Proof Opportunity
- Trust Seam
- Receipt Peek
- Recovery Ribbon

## Goals / Constellation Atlas

Required object behavior:

- Ambition Graph is the dominant object hierarchy.
- Goal detail becomes Orbital Lens.
- Proof and commitments orbit ambition/goal context.
- Pivot Preview shows what transfers and what becomes stale.
- Proof Capital shows proof state without gamified scoring.

Key primitives:

- Constellation Atlas
- Orbital Lens
- Ambition Graph Lens
- Proof Orbit
- Commitment Orbit
- Pivot Preview
- Proof Transfer Sheet

## Capture / Atmosphere Composer

Required object behavior:

- Composer stays quiet before input.
- Route Reveal appears after input.
- Meaning Router suggests proof/source/constraint/commitment/reflection/goal seed/held item routes.
- Correction Fold allows quick routing correction.
- Share Extension intake follows the same route model.

Key primitives:

- Atmosphere Composer
- Meaning Router
- Route Reveal
- Constraint Memory
- Correction Fold
- Intake Receipt

## Time / LifeShape Field

Required object behavior:

- Time shows life capacity and pressure, not a generic calendar clone.
- Simulation & Reflow Lab previews consequences.
- Undo Timeline records reversible changes.
- Recovery windows are visible as real capacity.
- Pressure affects Start Here through Reality Fit.

Key primitives:

- LifeShape Field
- Pressure Field
- Recovery Window
- Reflow Decision Fold
- Simulation Sheet
- Undo Timeline

## You / User System Profile

Required object behavior:

- You exposes Personal Runtime and local trust controls.
- Local Learning Inspector shows what Ambitions learned and used.
- OS Doctor shows data/source/proof/diagnostic health.
- Learning Receipts make adaptation visible.
- Reset/delete/disable controls are first-class.

Key primitives:

- User System Profile
- Personal Runtime Console
- Local Learning Inspector
- OS Doctor
- Data Control Panel
- Learning Receipt Detail

## Native Object Surfaces

Native surfaces must preserve the object loop:

policy guard -> command/event -> side-effect ledger -> receipt -> proof/trust trail

Eligible surfaces:

- Start Here widget
- Active Commitment widget
- Recovery Thread widget
- Proof Opportunity widget
- LifeShape Pressure widget
- Live Commitment Activity
- App Intents
- Share Extension
- Spotlight object results
- Control Center controls where appropriate

## Founder QA Overlay

Debug/development-only overlay:

- object ID
- object state
- recommendation trace
- source/proof links
- receipt path
- accessibility summary
- visual grammar state
- performance marker
- fixture identity
