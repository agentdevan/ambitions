# PXOS Train Control System

Status: PX01 future-canon complete; PXOS implementation not started
Date: 2026-05-02

## Start Rule

The PXOS train starts only when the user says exactly:

`Start PXOS Future-Canon Train`

or when the current user prompt explicitly preauthorizes Ambitions 4.0 global
sequence execution across PXOS and the selected batch dry-run says
`Execution allowed: YES`.

Routine global preauthorization does not replace proof, validation, source
truth, Red stops, human-proof stops, or product-decision locks.

## What Does Not Start PXOS

Creating PXOS canon, updating Beyond 3.0 roadmap, creating PXOS prompts,
completing REC closure, completing F30, or creating this train control system
does not start PXOS implementation.

## Required Before Implementation

- PXOS canon exists.
- Product decisions are locked/open/deferred in the ledger.
- REC claim boundaries are current.
- AOS dependency is checked for intelligence work.
- ME dependency is checked for large UI/file work.
- CS dependency is checked for route/raw/external/persistence work.
- Gate Matrix passes.
- Future batch prompt meets the PXOS Batch Prompt Standard.

## Auto-Continuation

Disabled by default. A PX batch may continue only after Green evidence, report,
registry/context/run-state update, commit, push, and train rules permitting the
next direct successor. Yellow/Red stops.

## Repair Triggers

Product-direction invention, new top-level surface, unsupported claim, missing
product decision lock, accessibility gap, visual genericness, source/trust gap,
ME/CS/AOS dependency gap, or unclassified validation failure.

## What PXOS Must Not Claim

PXOS must not claim implementation, shipped status, release readiness, App Store
readiness, TestFlight readiness, physical-device proof, production model
behavior, platform integration, AmbitionsOS implementation, AOS/ME/CS start, or
REC02 start.
