## Validation Plan

Every PD batch runs git status, diff check, Product Depth anti-sprawl scans, release-claim scans when copy or messaging is touched, doc QA advisory, batch-train gate advisory, changed-file boundary checks, and focused validation named by the batch prompt.

Implementation batches must also run relevant build/tests, copy/accessibility/product drift checks, file-size/diff-size checks, and compatibility scans. Weak or Missing validation is normally Red for implementation batches.

## Stop Conditions

Stop on product widening, new top-level tab, unsupported release/platform claim, PXOS/AOS implementation overclaim, forbidden file drift, missing ME/CS/AOS prerequisite, top-level stacked-card composition, unclassified validation failure, weak implementation validation, or any unresolved Red.

Auto-continuation is disabled by default. Continue only after Green evidence, report, registry/context/run-state update, commit, push, and the next direct successor being allowed. Yellow or Red stops unless Yellow is explicitly accepted and owned.
