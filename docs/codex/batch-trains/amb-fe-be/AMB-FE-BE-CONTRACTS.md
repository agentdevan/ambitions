# AMB-FE-BE Contracts

Status: Installed docs-only contract note

## Shared contract set

- Active top-level IA remains `Today / Goals / Capture / Time / You`.
- `Plan` stays an internal compatibility seam or contextual noun only where current truth allows it.
- Frontend contracts must bind the global shell to object-first surfaces and named flagship objects: Today -> Reality Meridian + Start Here, Goals -> Constellation Atlas, Capture -> Atmosphere Composer, Time -> LifeShape Field, You -> User System Profile.
- Frontend and handoff copy must treat source freshness, local proof, receipt/why-this paths, and accessibility fallbacks as mandatory contract terms whenever UI language is involved.
- No prompt in this train may create a new top-level destination, duplicate canon, or duplicate repo OS.
- No prompt may claim release, device, accessibility, privacy/legal, CI, hosted AI, hosted sync, custom cloud user-data storage, or integrated proof without current evidence.
- No prompt may widen into `.codex/runs/` staging, branch creation, or unrelated cleanup.
- No prompt may imply remote processing, cloud profiling, or a hosted personal-data backend when the contract only permits local-first or on-device-first behavior.
- Every prompt must include the runner header, active truth inspection list, allowed scope, forbidden scope, validation expectations, hard Red stops, rollback expectations, runner command, and final report format.

## Frozen downstream language

- The downstream batch language is frozen to the active IA exactly: `Today / Goals / Capture / Time / You`.
- `Plan` may appear only as compatibility-only or contextual language, never as active top-level IA.
- The only flagship object names to preserve in UI-facing contract language are `Start Here`, `Reality Meridian`, `Atmosphere Composer`, `LifeShape Field`, and `User System Profile`.
- The terms `source freshness`, `proof receipts`, `closure/recovery`, `protected time`, and `replay/restoration` are contract nouns only unless a later implementation batch proves them.
- Downstream prompts must not imply hosted AI, hosted sync, cloud profiling, remote processing, or a custom cloud personal-data backend.
- Downstream prompts must not claim implementation, accessibility, privacy/legal, release, device, CI, or performance proof unless current evidence exists.
- Frontend authority packet and preflight references are contract inputs only; they are not shipped UI proof and do not relax the no-claim boundary.

## FE contract emphasis

FE prompts must require visual proof references, accessibility proof references, and the exact screenshot/preview/report artifact names expected for a later UI-affecting handoff wherever the batch touches UI. These references are required handoff inputs only; they are not proof that the batch produced screenshots or accessibility conformance.

## BE contract emphasis

BE prompts must require explicit source/runtime/persistence seam naming and must not assume cloud, hosted AI, hosted sync, or user profiling. They must also state local-only boundaries for proof, replay, recovery, and retention when those seams are in scope.
