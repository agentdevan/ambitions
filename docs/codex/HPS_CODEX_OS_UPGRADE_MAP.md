## Purpose

This map makes HPS enforceable by Codex. It defines required reviewer skills, advisory scripts, reporting requirements, and stop conditions so HPS does not remain aspirational.

Create or invoke equivalent protocols for:

1. `human-progress-systems-architect`

If a physical skill file is missing, the batch must either create it, map to an equivalent CQS skill, or record accepted Yellow with owner before proceeding.

HPS-dependent batches should run or document inability to run:

- `scripts/hps-no-sprawl-scan.sh || true`
- `scripts/hps-moat-coverage-scan.sh || true`
- `scripts/hps-claim-boundary-scan.sh || true`

Scripts must be non-mutating by default and must not expose secrets or sensitive data.

## When HPS review is mandatory

HPS review is mandatory when a batch touches:

- life visibility
- Found Life
- Human Progress Graph
- commitments
- open loops
- searchable recall
- memory correction/deletion/rejection
- proof/evidence
- source truth
- requirement graphs
- recommendations
- Start Here intelligence
- option value
- pivot preservation
- dream handling
- local/on-device intelligence
- AI governance
- vertical expansion strategy
- education/career/workforce/family/coaching strategy
- acquisition/moat strategy
- widgets/Live Activities/notifications/App Intents containing sensitive life projections

## Required batch-report additions

HPS-dependent batch reports must include:

- HPS primitives touched
- HPS gates invoked
- no-sprawl proof
- five-tab coherence proof
- rendered-proof status when UI-affecting
- recommendation quality status when recommendations touched
- proof/source status when proof/source touched
- privacy/memory permission status when recall/memory touched
- AI governance/evaluation status when intelligence touched
- vertical no-build status when vertical strategy touched
- acquisition/no-claim boundary status when moat/business strategy touched
- unresolved Yellow items with owner

## Hard Red additions

Stop on:

- surface drift after visual proof
- missing rendered proof for visible UI without owner
- fake confidence / AI theater in recommendation
- source-free career/education/professional certainty
- inferred memory presented as fact
- private life content exposed externally by default
- unreviewable memory/recommendation/proof mutation
- vertical product implementation without approval
- hosted AI/user-data-server claim without implementation/legal review
- acquisition/bidding/valuation claim without evidence

## Closeout

HPS12 must verify that every HPS-dependent later train has a review path. Missing review path is Yellow only if the owner and repair batch are recorded; otherwise Red.
