# LDI Fixture Strategy

<!-- markdownlint-disable MD013 -->

Status: Future fixture strategy. Fixture implementation is not claimed until LDI21 or owned earlier gates run.

## Fixture Families

LDI fixture coverage must span all 45 families named in `docs/canon/AmbitionsOS_LDI_Evaluation_And_Governance.md`.

## Product Fixture Requirements

Fixtures must cover normal tasks, notes, one-step goals, project goals, life-defining dreams, regulated goals, unsafe and crisis-coded inputs, fantasy/impossible dreams, source-stale/source-conflict/source-change states, jurisdiction changes, capacity collapse, privacy-sensitive goals, iCloud unavailable/conflict states, corrupt pack/import states, notification privacy leaks, accessibility overload, adversarial unsafe prompts, unsupported domains, user seriousness changes, rejected assumptions, superseded/withdrawn sources, and active/parked conversions.

## Evidence

Each fixture should record input, primary lane, secondary flags, safety/professional/source/privacy states, required receipt, activation eligibility, required user review, and forbidden claims.

## Advisory Mode

Before fixtures exist, scripts may report advisory Yellow only. Once LDI21 creates fixture manifests, missing family coverage is Red.
