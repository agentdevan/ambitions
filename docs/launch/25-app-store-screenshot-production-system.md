# Ambitions App Store Screenshot Production System

Status: Draft
Purpose: Production system for App Store screenshot strategy, capture, QA, and final export

## Objective

The App Store screenshots must make Ambitions understandable in seconds.

The viewer should immediately understand:

- Ambitions helps people accomplish goals
- goals become grounded daily steps
- daily steps adapt around real life
- the product feels premium and native to iPhone
- the system is private by design

## Primary launch promise

Finally know how to accomplish your goals.

## Screenshot set

The launch screenshot set should contain five primary frames:

1. Today / Reality Meridian
2. Goals / Constellation Atlas
3. Time / LifeShape Field
4. Recovery / Closure
5. You / Trust

## Screenshot order

The screenshot order should tell this story:

1. Shape today around what matters.
2. Goals become grounded daily steps.
3. Built around real life.
4. Real life changes. Ambitions adapts.
5. Private by design.

## Design requirements

Screenshots must feel:

- premium
- native iPhone-first
- calm
- grounded
- emotionally stable
- visually mature
- category-defining

Screenshots must not feel like:

- a task manager
- a habit tracker
- a chatbot
- a productivity dashboard
- a calendar clone
- a web app

## Visual direction

Use the Ambitions visual system:

- dark graphite/OLED foundation
- restrained celestial atmosphere
- native iPhone realism
- quiet luxury spacing
- premium typography hierarchy
- subtle glow and depth
- intelligent but non-flashy surfaces

## Copy system

Headline copy must be short, direct, and premium.

Preferred headline set:

1. Shape today around what matters.
2. Goals become grounded daily steps.
3. Built around real life.
4. Real life changes. Ambitions adapts.
5. Private by design.

## Production states

Each screenshot requires a believable seeded user state:

- meaningful goal
- realistic daily schedule
- grounded recommended step
- visible continuity
- realistic recovery or closure state
- privacy/trust settings

No screenshot may use placeholder content, lorem ipsum, fake debug data, or generic productivity examples.

## QA gates

A screenshot is Green only if:

- it communicates one primary idea
- the UI looks production-faithful
- the copy is readable
- the content is believable
- the visual system feels native and premium
- the frame does not resemble a generic productivity app
- canonical tab names are correct
- there are no placeholder states

Yellow if:

- the concept is correct but visual polish is not final
- the copy is readable but not sharp enough
- the seeded data is plausible but not ideal

Red if:

- the screenshot feels generic
- the screenshot looks like a dashboard or task list
- the screenshot implies unsupported functionality
- the screenshot uses non-canonical product language
- the screenshot misrepresents privacy, AI, or implementation behavior

## Device strategy

Initial production should target iPhone portrait first.

Recommended capture/export targets:

- 6.9-inch iPhone display class
- 6.7-inch iPhone display class
- 6.5-inch fallback if required
- 6.1-inch review checks

Final sizes must be confirmed against current App Store Connect requirements before submission.

## Screenshot proof packet

Each screenshot should have a proof packet containing:

- source screen
- build/version
- device/simulator target
- seed data profile
- accessibility check status
- visual QA status
- final export path
- known limitations

## Final rule

Do not ship screenshots that merely show features.

Ship screenshots that make the category understandable, trustworthy, and desirable.
