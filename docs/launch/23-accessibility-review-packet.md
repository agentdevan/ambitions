# Ambitions Accessibility Review Packet

Status: Draft
Purpose: Accessibility launch-review framework

## Accessibility philosophy

Ambitions should feel calm, understandable, and usable across different accessibility needs.

Accessibility is not decorative compliance work.

It is part of product trust.

## Required launch checks

### Dynamic Type

Verify:

- readable hierarchy
- no clipped layouts
- preserved one-primary-object structure
- usable onboarding
- readable Start Here surfaces

### VoiceOver

Verify:

- correct reading order
- understandable labels
- logical navigation
- meaningful announcements
- usable Today navigation

### Reduce Motion

Verify:

- core flows remain understandable
- orientation is preserved
- transitions remain coherent
- important state changes remain visible

### Contrast

Verify:

- readable graphite/OLED surfaces
- accessibility-safe typography
- non-color-dependent meaning

### Touch targets

Verify:

- comfortable tap areas
- clear primary actions
- accessible closure controls

## Accessibility launch blockers

Red if:

- onboarding becomes unusable
- Today becomes unreadable
- VoiceOver navigation breaks
- core actions are inaccessible
- Dynamic Type breaks layout severely

Yellow if:

- accessibility improvements are identified and bounded
- non-critical polish remains

Green if:

- core flows remain understandable and usable
- primary interactions remain accessible
- trust and orientation remain preserved

## Accessibility tone

Accessibility behavior should preserve:

- calmness
- clarity
- continuity
- reduced cognitive overload
- grounded orientation

## Final accessibility rule

Accessibility should reinforce the feeling that Ambitions is a trustworthy life system, not a visually impressive app that collapses under real use conditions.
