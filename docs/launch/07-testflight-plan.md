# Ambitions TestFlight Plan

Status: Draft
Purpose: Beta readiness, feedback operations, and launch-risk reduction

## TestFlight objective

TestFlight should verify whether real users understand, trust, and return to Ambitions.

The first beta is not only a bug hunt. It is a category-comprehension, onboarding, trust, and goal-to-step believability test.

## Primary beta questions

1. Do users understand what Ambitions is?
2. Do users believe Ambitions can help them accomplish goals?
3. Do users trust the system with personal life information?
4. Do users understand what to do today?
5. Do users want to come back tomorrow?

## Primary beta cohort

Overwhelmed goal-setters.

These are users who have meaningful goals but struggle to turn them into realistic daily action.

## Secondary beta cohorts

- Ambitious professionals
- Creators and builders
- Privacy-conscious Apple users
- People with complex schedules
- Users who have abandoned productivity systems before

## Beta phases

### Phase 1: Comprehension beta

Goal: determine whether users understand the product.

Focus:

- onboarding clarity
- category comprehension
- first goal setup
- first Start Here experience
- privacy trust

### Phase 2: Believability beta

Goal: determine whether goal-to-step recommendations feel grounded.

Focus:

- recommendation clarity
- time fit
- step quality
- explanation quality
- recovery behavior

### Phase 3: Retention beta

Goal: determine whether Ambitions creates enough value to return.

Focus:

- day-two return
- week-one usage
- recovery after missed days
- trust in recommendations
- goal continuity

### Phase 4: Submission beta

Goal: stabilize for App Store submission.

Focus:

- crash-free use
- visual polish
- accessibility
- privacy disclosures
- App Review readiness
- launch-blocker closure

## First-session test script

Ask testers to:

1. Install Ambitions
2. Complete onboarding
3. Create one meaningful goal
4. Add basic availability or schedule context
5. Open Today
6. Review Start Here
7. Open the recommended step
8. Complete or close the step
9. Review privacy/trust settings
10. Submit feedback

## Day-one feedback questions

- What did you think Ambitions was for?
- Did you understand what to do first?
- Did your first goal feel easy to enter?
- Did the recommended step feel believable?
- Did the app feel different from a productivity app?
- Did anything feel confusing, generic, or untrustworthy?
- Would you open it tomorrow?

## Day-three feedback questions

- Did Ambitions help you make progress?
- Did the system still feel relevant after real life changed?
- Did Start Here continue to make sense?
- Did you trust the recommendations more or less over time?
- What made you hesitate to return?

## Week-one feedback questions

- Did Ambitions make your goals feel more achievable?
- Did the app help connect goals to daily action?
- Did recovery behavior feel useful?
- Did privacy/trust feel clear enough?
- What would stop you from paying for it?

## Launch blockers from beta

Red if:

- users do not understand the product
- onboarding fails to create a goal-to-step moment
- recommendations feel random or generic
- users do not trust the system
- app feels like a habit tracker, task manager, chatbot, or generic productivity app
- privacy language feels unclear or overclaimed
- core flows crash or lose data

Yellow if:

- users understand the product but need better language
- some recommendations feel generic but the mechanism is understood
- trust is acceptable but support copy needs strengthening
- visual polish is close but not final

Green if:

- users understand Ambitions quickly
- first goal setup is clear
- first recommended step feels believable
- users trust the system enough to continue
- users describe the product as distinct from productivity apps
- users want to come back tomorrow

## Beta evidence packet

Each TestFlight cycle should produce:

- tester cohort description
- build number
- device and iOS coverage
- onboarding completion rate
- first goal creation rate
- Start Here open rate
- first step completion or closure rate
- qualitative feedback themes
- top confusion points
- top trust concerns
- launch blocker list
- next build priorities

## Beta closeout rule

Do not call a beta successful because testers were polite.

A successful beta must show evidence of understanding, trust, goal-to-step believability, and return intent.
