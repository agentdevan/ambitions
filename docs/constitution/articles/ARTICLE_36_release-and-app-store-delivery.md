# Article 36 — Release and App Store delivery

## RELEASE-001 — Exact release identity

Every release candidate is tied to one commit, generated project state, dependency lock state, build number, configuration, signing identity, environment, and evidence manifest.

## RELEASE-002 — Required release domains

Release acceptance includes build, tests, migrations, accessibility, privacy manifest, required-reason APIs, security, performance, physical-device matrix, extensions, account/entitlement, archive/export, App Store metadata, support/privacy URLs, review notes, and rollback.

## RELEASE-003 — Phased rollout and rollback

Release design defines staged rollout, monitoring, stop criteria, rollback/forward-fix policy, migration constraints, and emergency hotfix path.

## RELEASE-004 — No unsupported readiness

TestFlight, App Store, privacy, accessibility, performance, CloudKit, R2, account, or device readiness claims require current exact-commit evidence and required independent approval.
